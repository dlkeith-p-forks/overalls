# Mila M2–M4: terminals, threads and web (2026-10-18)

Scope: the Mila client side of
[ADR-0220](../decisions/0220-mila-client-over-porsche-ssh.md),
[ADR-0222](../decisions/0222-porsche-client-commands.md),
[ADR-0223](../decisions/0223-porsche-terminal-attach.md) and
[ADR-0226](../decisions/0226-monospace-web-on-flutter.md). Reviewed
against the uncommitted working tree on branch `feat/mila-mila-ui`, based
on `f49f350d`. The Porsche commands themselves (`thread`, `terminal`, `web`,
`watch`, `terminal attach`) belong to other workstreams; this review covers
only what Mila sends, accepts and shows. Their result shapes are pinned by
`protocol/test/fixtures/porsche_client_results.json` and
`protocol/test/fixtures/terminal_attach.json`, which are copied from those
workstreams.

**Execution status:** by instruction, the code was written first. Apart from
an early run of `ssh_command_test.dart` and `client_results_test.dart`, no
test, analyser or Nix build has run against the final tree. Every finding
below describes the design and the tests written for it, not passing runs.

## Findings

1. **Boundary:** Mila still adds no Marshall API. Every new action is an
   ordinary Porsche command produced by `encodeCommand`, which validates the
   catalogue. The catalogue covers `thread ls/show/turns/prompt/answer/plan
   approve/plan revise/mode/read`, `terminal ls/new/kill/attach`, `web
   show/set` and `watch`. It also enforces the cross-option rules: `web set`
   needs a change and never both `--public` and `--private`; `watch` takes at
   most 16 filters and at least one machine, thread or session filter. Deep
   links still only navigate. The opened page then reads, and a thread page
   moves its read marker.
2. **Payloads off the command line:** prompts, answers and plan revisions
   end with a `-` argument and travel on the exec channel's stdin, at most
   64 KiB of valid UTF-8 (`mila-stdin-payload-bounded`). The widget tests
   assert that the prompt text never appears in any command line.
3. **Mutations once:** every thread, terminal and web mutation carries a
   fresh request id and is polled through `request show`, as in M1. `web
   set` sends the shown `policy_revision`, so a concurrent change comes back
   as a conflict and is never overwritten.
4. **Terminal attach:** `TerminalAttach` is a pure state machine with
   attaching, attached, waiting and ended phases, checked by a Hegel
   `StateMachine`.
   - The cursor is monotone except for one documented jump: when an attached
     header's `from` differs from the cursor, the screen resets and the jump
     is counted.
   - Output that arrives before the header has no position and is dropped.
   - Read-only, whether chosen or granted, never sends input or resizes
     (`mila-read-only-never-sends`).
   - Refusals and authority loss end the view. Transport loss retries with
     backoff, at most 8 attempts.
   - The header is one closed JSON line of at most 512 bytes
     (`mila-attach-header-closed`).
5. **Terminal bytes:** output passes from the PTY channel through a
   streaming UTF-8 decoder into the in-memory xterm emulator, which keeps
   10,000 lines of scrollback. Terminal bytes are never written to disk,
   cache, preferences, logs or controller state
   (`mila-terminal-bytes-never-at-rest`). A paste is bracketed and stripped
   of control sequences and of its own end marker
   (`mila-paste-cannot-escape`).
6. **Watch:** `watch` is decoded line by line, with bounded lines and
   strict ids. Unknown event kinds are ignored. Silence beyond 40 seconds
   reopens the stream, and transport loss reconnects with backoff of 1 to
   60 seconds. Authority loss stops the watch, and an error envelope or exit
   status 3 counts as authority loss. A watch event only triggers a re-read
   through the ordinary commands; it never carries state into the UI.
7. **Web:** only an HTTPS URL on a DNS host, with no user info and no
   fragment, is accepted. Public endpoints open in an in-app webview on iOS
   and Android, and the webview's navigation delegate allows only HTTPS.
   Private endpoints always open in the system browser, so Mila never hands
   Marshall browser credentials to a webview. Copy uses the clipboard, and
   share uses a new `share` platform-channel method.
8. **Presentation:** the M2–M4 screens use the Monospace Web tokens and
   glyphs. The new `Segmented` and `TopTabs` widgets and the
   `monoTerminalTheme` keep colour literals in `tokens.dart`. The terminal
   view is forced left to right inside right-to-left locales. All 87 new
   strings are in all 27 ARB catalogues.

## Gaps

- Stock OpenSSH merges a PTY channel's stderr into its output, so the
  attach header path is proven only in memory (`channels_test.dart`). The
  OpenSSH journey covers the PTY size, window change, input and exit-status
  mapping.
- The `mila-desktop` machine test does not cover these screens: its fixture
  cannot provision a guest machine, so it has no terminal or thread to open.
- iOS and Android share sheets and the webview have not been built or run
  on a device.
- The goldens `terminal_ar.png` and `thread_ar.png` are not generated yet,
  and the machine goldens must be regenerated because the machine list
  gained a threads button.
