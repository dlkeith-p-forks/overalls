## Findings

### High: destination peer attestation is absent

Galileo can forward a peer token and Marshall exposes verification, but Audi
does not verify that token or inject `x-kittens-source-vm`. The accepted trust
boundary in ADR-0079 is therefore incomplete and peer use is not production
ready. Implement the destination flow and a real two-guest denial/success test.

### High: peer token implementation differs from the accepted decision

`Marshall.Galileo.PeerTokens` is a stateless HMAC prototype. ADR-0079 selected
short-lived digest-backed tokens verified through Marshall. Implement the
accepted lifecycle or replace the decision with an explicit stateless design;
the current code is not evidence for digest-only storage.

### High: request uploads are buffered

Audi and Galileo each read a bounded request body before forwarding it. This
does not implement ADR-0080's end-to-end streaming/backpressure requirement and
can retain two copies of a 16 MiB upload. Stream uploads before marking the
decision implemented.

### High: exactly one team owner is not database-enforced

The partial unique index enforces at most one owner, not at least one, and
account retirement does not resolve sole ownership. Coordinator fixes in this
milestone prevent admins removing admins and recheck transfer guards under the
team lock, but retirement and the nonzero-owner invariant remain open.

### Medium: machine evidence was overstated

`galileo-service` proves the packaged Galileo release, credential loading,
verified synthetic TLS, header injection, strip-prefix handling and denial of
malformed bindings. `private-services-network` proves packaged Audi DNS/TLS in
network namespaces. Neither proves real Marshall attachment state, Firecracker
execution fencing or peer attestation across two guests. ADRs and the Galileo
ledger now state those limits.

## Follow-up work

The four high findings were resolved later in the milestone worktree:

- Audi and Galileo now forward uploads one bounded chunk at a time with
  synchronous destination sends and no retries. The packaged Galileo test passed
  exact byte/digest verification for an upload larger than three source chunks.
- Marshall now persists only peer-token digests, consumes one unexpired row
  atomically using database time and reclaims expired rows in bounded batches.
- Destination Audi now verifies peer tokens before opening the guest connection,
  strips peer authority and caller provenance, and injects one attested source VM.
- Deferred database triggers now require exactly one active team owner at commit;
  retirement refuses owners and transactionally archives other memberships and
  pending transfers under deterministic locks.

ADR-0080, ADR-0077 and ADR-0079 remain partial. Real Marshall/Firecracker
guest-path acceptance, a deployed source-Galileo-to-destination-Audi peer flow,
stalled-hop backpressure, independent-node team race coverage and Marshall's full
application gate remain open. The original findings above are retained as the
review history that prompted these corrections.

## Renewable authority follow-up

A later physical `galileo-fleet` run reached sustained guest load but found that
an already admitted stalled origin remained active after Lilly stopped the source
VM. ADR-0080 now requires short renewable authorization leases rather than
treating initial admission as indefinite authority. Marshall repeats the source
execution, owner and attachment fences without returning credentials, routes or
new peer tokens. Galileo converts the relative TTL to a monotonic deadline and
closes the original single attempt after refusal, invalid response, authority
delay or expiry.

Focused protocol tests cover closed bounded lease messages; Marshall domain and
Plug tests cover JSON-safe authorization, renewal and stop fencing; Galileo tests
cover refused and late renewal against one real TLS attempt. A source-filtered
physical `galileo-fleet` rerun then passed the execution-stop subtest in 26.14
seconds: the stalled origin was cancelled, `galileo_active_requests` drained to
zero, and the restarted VM obtained fresh authority. The run failed in the next
cross-host peer request with a transport error while Marshall connections
exceeded the fixture's 500 ms checkout budget. This proves physical lease
cancellation but not peer or complete fleet acceptance; ADR-0080 remains partial.
