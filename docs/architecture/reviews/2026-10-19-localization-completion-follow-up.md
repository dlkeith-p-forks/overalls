# Localization source and acceptance follow-up

This follow-up starts from `b2899911f` and preserves ADR-0201 and ADR-0207.
The prior completion statement was too broad: complete extracted catalogs did
not prove that every human string entered extraction, and the ordinary Marshall
catalog alias did not enforce its strict mode. No new domain, durable authority,
protocol, supported locale or accepted presentation decision is introduced.

## Implementation review

Native feature lookups now cover pin controls and accessible names, clone host
failure explanations, clone/resize screen-reader stages, context and inference
fallbacks, finite inference and workload states, thread-command labels and
descriptions, administrative deletion progress and the fixed redacted job-error
explanation. Authoritative state atoms, data attributes, command names, stored
projections, JSON and exported machine data remain unchanged. Raw administrative
exception details are never used as translation identifiers or browser text.

Sign-out uses the authentication library's supported runtime text overrides.
The existing confirmation component retains its DELETE action and CSRF form;
an early privacy hook and the post-authentication locale hook apply browser
selection and the saved self-only override. Rendering performs no revocation
and introduces no account selector or authorization rule. Xterm's two public
accessibility strings are assigned before terminal construction; its vendor
sources and terminal output bytes are unchanged.

The checker now enforces completeness by default, and precommit explicitly
requests strict mode. Diagnostic report-only mode still rejects structural
errors and invalid invariant reviews. Added subprocess regressions exercise the
actual checker entrypoint with empty, partial-plural, fuzzy, copied and reviewed
forms. Catalogs remain native per-language/per-feature files; source-English
handbook bodies and titles remain excluded from translation.

The destructive peer-budget restart property now owns its fault-injected
supervisor instead of exhausting the application supervisor. It preserves the
registered budget API, capacity, live TLS assertions, deadlines and 100 cases,
then restores the original retained child specification after fixture shutdown.
This is test ownership under ADR-0191 and ADR-0083, not a change to production
supervision or evidence of native guest recovery.
