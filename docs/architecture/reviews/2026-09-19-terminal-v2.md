# Terminal v2 review

- Date: 2026-09-19
- Scope: guest terminal multiplexer, persistent host stream, browser workspace
- Decisions: [ADR-0082](../decisions/0082-guest-terminal-multiplexer.md),
  [ADR-0083](../decisions/0083-terminal-host-stream-and-registry.md),
  [ADR-0084](../decisions/0084-browser-terminal-workspace.md);
  supersedes ADR-0019/0020/0021/0022

## Assessed against

The serial console path (single ttyS0 through dtach, 100 ms polls at three
hops, encrypted PostgreSQL mailboxes, writer-epoch fencing) was removed
end to end. Terminal bytes now flow browser WebSocket → Marshall viewer
channel → persistent host stream → guest vsock multiplexer PTY, with sessions
and raw scrollback durable in the guest.

## Executed verification

- Guest daemon: `cargo test` (26 tests: SHA-256/HMAC vectors, framing bounds,
  ring model, PTY login-shell execution with TERM/COLORTERM/winsize/home
  assertions, vsock loopback end-to-end create/attach/marker/kill) and
  `cargo clippy --all-targets -- -D warnings`, run by the nix check
  derivation `legacyPackages.terminaldChecks`; `nix build .#terminald`
  produces the static musl binary; both guest images build with the daemon
  and unit installed (`nix build .#guest`, `nix build .#ubuntu-guest`).
- Protocol: StreamData property tests for frame round trips, truncation,
  declared-length bounds, control closed schemas, deduplicated listings and
  attach/created coherence (`protocol` precommit: compile, format, tests,
  Dialyzer, contracts).
- Lilly: full suite (310 tests, 36 properties) and precommit including
  Dialyzer; new terminal tests cover WebSocket masking/length encodings and
  hello key derivation; actor tests cover terminal identity authorization and
  supersession denial; relocation suites cover capability gating through the
  new authority.
- Marshall: a clean-database full suite reached 716/718 tests (60 properties),
  with only the two independently reproduced Audi baseline failures. Focused
  tests cover stream hello binding, coalesced framing, sequence deduplication,
  shared single-use tickets, registry/listing identity and local fleet health.
  Browser node tests cover copy-on-select newline shaping.

## Known limits (honestly held)

- The Audi login-denial and ingress SSH-stream tests fail identically on
  `main` before this change (verified against the main worktree); they are
  pre-existing environment-dependent failures, not terminal v2 regressions.
- No real-machine KVM run of the full path was executed in this change: the
  fleet browser scenario and smoke harness updates are specified but their
  nested-KVM execution remains outstanding, so end-to-end guest typing,
  reattach and boot-log behavior through a real Firecracker guest is not yet
  re-verified after the rewrite.
- Interactive latency, reconnect storms and sixel-heavy throughput are
  unmeasured; memory bounds are enforced by design (viewer high-water pause,
  ring budgets) but not load-tested.
- Fleet monitoring surfaces reported protocol and local stream readiness;
  dedicated historical terminal service panels remain follow-up work.

## Findings

The removal eliminates the mailbox secret-handling surface and the
at-most-once input machinery; replay safety now rests on per-channel input
sequences and guest-side session tokens, which are simpler and property
tested. Authority chains are shorter: ticket (browser) → Cedar + capability
gate (Marshall) → execution-session-bound stream (host) → boot-bound HMAC
(guest). Host stream discovery uses distributed registration only after the
authenticated hello, and ticket one-use authority is a hashed PostgreSQL row,
so either side may land on any Marshall replica. Boot-log capture replaces the
dtach process-tree root; systemd still
owns the VMM lifetime, and removing the root ttyS0 autologin closes an idle
root shell that previously existed on every guest.
