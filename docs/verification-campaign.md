# User-operation verification campaign

Started 2026-09-25 from `253cdcaa`. This is an implementation and execution
ledger, not a statement that the application is fully verified. The campaign
covers current documented capabilities, including missing implementations after
following ADR supersession chains. Production deployment is excluded.
At the user's request, new Inception tests and validation are excluded; historical
evidence retains its original scope.

## Delivery contract

Each improvement has one agent, one `verify/NNN-topic` branch and a separate
worktree. At most three improvement agents implement concurrently; a coordinator
reviews and integrates one completed improvement at a time. Initially only one
heavyweight NixOS machine build runs at once. Test databases, ports, build caches
and temporary state are isolated between worktrees.

Before implementation, record the user operation, allowed result, refusal,
failure/recovery cases, independent property oracle, native boundary, dependencies
and required checks. Implement bounded defects with their regression tests.
Separate larger capability implementations into dependent improvements. New
architectural choices are delegated by the user and require explicit rationale
and ADR maintenance; accepted rationale must not be silently rewritten.

Every delivery includes contracts, scoped execution evidence, relevant handbook
and scenario changes, reviewed receipts, and architecture impact. The coordinator
integrates current main, resolves conflicts, checks the integrated candidate,
merges and pushes main, and verifies the remote revision. Failed gates prevent
integration. Branch protection is respected. Destructive scenarios use disposable
machines only.
Hosted Antithesis bootstrap validation admits up to five active attempts globally; each attempt remains bound to its immutable identity, exact policy duration and triage receipt.

## Evidence and completion

Use properties against real behavior with an independent oracle, and packaged
NixOS journeys for the corresponding native boundaries. Record seeds and minimal
failures. A generated model tested only against itself is not application evidence.
Run focused tests, required component precommit/type/contract gates, and required
ADR/HLDD checks; shared protocol changes require both consumers. Add checks to the
explicit Nix catalog so new files are executable checks.

`present` means an inspected assertion exists. `recorded` requires exact supporting
execution text. Keep `partial` until scoped native and property evidence justify
the handbook's stronger status. External providers, physical independent failure
domains, production activation and native macOS remain explicit acceptance
boundaries. Missing local implementation or reproducible failures remain unfinished
campaign work. Completion requires every discovered current capability to have
scoped evidence or a specific external blocker, with no concealed local failures.

Architecture impact of this ledger: no runtime, protocol, authority or persistence
change. It documents work and evidence obligations under existing ADRs; subsequent
improvements assess their own impact. The initial inventory is not exhaustive
semantic verification and will grow as source inspection identifies journeys.
