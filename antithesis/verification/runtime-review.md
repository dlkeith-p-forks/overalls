# Runtime seam review (2026-10-13)

Scope: current staged and unstaged foundation diff for the eight Mix projects and application startup hooks, Lilly Control configuration/runtime/pool type, the hosted Lilly adapters, and the Nix release selectors. This is a source review of the new harness seam, not a completed release build, native guest run, or hosted Antithesis run. Applicable decisions are ADR-0017 (physical ownership, actors, journals, readiness and cleanup), ADR-0033 (real machine-test evidence), and ADR-0149 (state-only outcomes and independent diagnostics). The root and component contracts require unavailable observations to withhold credit and prohibit controlled effects from claiming unobserved physical success.

## Findings and disposition

1. **Resolved in this diff — controlled delete and stop initially fabricated physical outcome facts.** The first review found `ControlledExecutor.reconcile/3` mapped a JSON command marker to `:deleted` or `:stopped` with `compute_empty: true`, `disk_present: false`, and `cleanup_complete: true`. That marker does not observe a VMM, cgroup, disk, or cleanup, so a delivered retained command could have released durable obligations without ADR-0017 physical proof. The revised `antithesis/lilly/lib/overalls_antithesis/lilly/controlled_executor.ex:17-21` always returns `{:retry, :execution_unavailable}`; its marker explicitly says `controlled_operation_publication_only` at `:63-73`. The targeted test now asserts that delete cannot settle a physical outcome. Publication success or failure cannot create a lifecycle receipt.

2. **Resolved as a fail-closed placeholder — advertised guest Lilly variant initially named a missing executor.** `lilly/lib/lilly/control/runtime.ex:19-20` selects `OverallsAntithesis.Lilly.GuestExecutor` under the guest build flag, and `antithesis/nix/images.nix:4-8,67-73` exports `lilly-guest`. The first review found no module implementation, so an actor command would fail at callback dispatch. The revised `antithesis/lilly/lib/overalls_antithesis/lilly/guest_executor.ex:1-35` implements the callbacks with unavailable/retry results, and guest unit verification refuses even an empty command list, fencing guest-mode actor initialization. The selected callback module is now defined, but the guest release build is still unverified. This placeholder cannot complete the guest Control path and provides no QEMU, Firecracker, ZFS, boot, or physical execution proof. A real guest adapter and recovery inventory remain unimplemented.

## Boundaries confirmed by source

- Ordinary `Pool.new/4` and its ZFS inspection are unchanged. `lilly/lib/lilly/control/config.ex:250-284` replaces only the harness-compiled pool decoder; the hosted decoder sets `backend: :controlled`, requires a configured identity and existing path, and does not inspect ZFS. `antithesis/lilly/lib/overalls_antithesis/lilly/collector.ex:17-44` reports every controlled pool unavailable with no capacity totals. `lilly/lib/lilly/control/runtime.ex:473-485,1063-1078` forces hosted `execution_ready: false` and local readiness false. Marshall admission requires both readiness and fresh pool credit (`marshall/lib/marshall/compute/admission.ex:199-218`), so ordinary real VM admission cannot pass this hosted boundary. A real ZFS/native adapter and proof are prerequisites for native admission.
- The production path remains selected by the absence of the compile flag: `lilly/lib/lilly/control/runtime.ex:24-29` uses the original Collector, ZFS I/O, Ownership, and Executor, while `config.ex:259-284` retains `Pool.new/4`. The application child lists and Lilly `:rest_for_one` spine are otherwise unchanged; the wrapper runs after supervisor success. The eight applications each add the SDK dependency only when `ANTITHESIS_HARNESS=1`, independent of each other; `nix/domains/artifacts/applications/source.nix:22-31` includes SDK source only for that selector. `nix/domains/artifacts/default.nix:57-72,106-125` supplies matching selectors to dependency fetch and release compilation. This is source evidence only, pending ordinary and flagged compiled release checks.
- Each application startup hook has one literal `reachable` callsite gated by a successful supervisor result and `declare_catalog([__MODULE__]) == :written`. Catalog declaration precedes evaluation. These hooks show application startup, not readiness of the full service graph or setup completion. The SDK lifecycle signal remains owned by the workload bootstrap.
