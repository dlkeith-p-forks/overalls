# BEAM fallback SDK independent review

Review date: 2026-10-13. Scope: `antithesis/sdk/` source and its local tests. This review does not credit other harness integration, image execution, or an Antithesis hosted run. The reviewer changed no SDK implementation files.

The documented [fallback SDK](https://antithesis.com/docs/reference/sdk/fallback/) requires each SDK message to be one atomically written, newline-terminated JSON object in `$ANTITHESIS_OUTPUT_DIR/sdk.jsonl`. The [environment contract](https://antithesis.com/docs/configuration/the_antithesis_environment/#capturing-output) makes that directory a write-only capture sink in Antithesis; a local file readback does not prove hosted ingestion. The [assertion format](https://antithesis.com/docs/reference/sdk/fallback/assert/) requires startup declarations and stable string IDs; the [schema](https://antithesis.com/docs/reference/sdk/fallback/schema/) alone does not enforce that temporal relationship. The [lifecycle format](https://antithesis.com/docs/reference/sdk/fallback/lifecycle/) uses one `antithesis_setup` record. Direct `/dev/urandom` reads are supported by the [random device documentation](https://antithesis.com/docs/configuration/the_antithesis_environment/#random-devices).

## Findings from initial implementation and correction

1. **Must fix: poison was lost on application restart.** `Writer.init/1` created a new admission atomic and `Port.open` helper on each restart (`lib/overalls_antithesis/sdk/writer.ex:58-81`). A short first write poisoned only the former writer/helper, so restarting the SDK reopened the same output and admitted another record. A narrow local reproduction returned `{:error, :uncertain}`, `:poisoned`, then after `Application.stop/start`, `:ready` and `:written`. The captured bytes were two setup objects concatenated without a separator between them: `{"antithesis_setup":{"status":"complete"}}{"antithesis_setup":{"status":"complete"}}\n`. This violates the local `sdk-admission-before-mailbox` and `sdk-atomic-append` contracts and the no-recovery rule in [BEAM SDK feasibility](../scratchbook/beam-sdk-feasibility.md). Hosted output cannot be reread to repair the stream. A sticky run-level poison or fail-stop is required before a restarted writer can admit output.
2. **Must fix: native frame validation accepted non-JSON.** The initial `valid_frame` checked only outer braces, newline placement, CR and NUL (`native/sdk_writer.c:33-39`). A compiled-helper probe sent the length-prefixed bytes `{"x":}\n`; it returned framed `W` and appended those exact bytes. The first six tests only sent `bad\n`, which does not exercise malformed JSON with the expected wrapper. A full JSON object validation boundary is required before writing to the capture file.
3. **Catalog guarantee gap: dynamic undeclared evaluations were accepted.** `SDK.evaluate/3` accepted any caller-built `%Property{}` whose fields had the expected shapes (`lib/overalls_antithesis/sdk.ex:90-114,170-181`); it did not require a property produced by a literal macro or declared catalog. A narrow local probe emitted `:written` with `id: "undeclared dynamic ID"` and no declaration. Antithesis says it will attempt to evaluate undeclared assertions, so the public path weakens the module's literal/catalog guarantee. No untrusted caller was found in this SDK-only review; enforce provenance or state and audit the trusted-caller boundary before claiming all emitted assertions are reviewed literals.
4. **Status was misleading when disabled or unavailable.** `Writer.init/1` stored those states (`lib/overalls_antithesis/sdk/writer.ex:64-69`), while `status/0` examined only the admission atomic and returned `:ready` (`:39-51`). This can mislead readiness code; a subsequent submit returns `:disabled` or `{:error, :unavailable}`. The status function should describe the sink state or callers must not treat it as delivery readiness.

The implementation agent subsequently added full JSON/UTF-8 parsing before append, preserved the poison slot across SDK application restarts within one BEAM VM, made `status/0` reflect disabled/unavailable, and checked evaluation descriptors against their generated module catalog. An independent re-probe of the revised production helper returned `I` for `{"x":}\n`, `W` for the valid setup object, and captured only the valid line. The revised SDK test for short writes stops and restarts the application and verifies that the partial bytes remain unchanged. Test-only fault controls are now behind `SDK_WRITER_TEST_FAULTS`; the image build compiles without that definition.

**The cross-process restart fault was also corrected.** The in-VM `:persistent_term` slot cannot survive a BEAM VM/container restart or coordinate separate command processes. A second direct-helper probe before this correction returned `P` for a short first write, then `W` from a fresh helper for the same `sdk.jsonl`, concatenating two objects. The revised helper now takes a nonblocking `flock` on a private state directory and creates/fsyncs an `inflight` marker before touching the sink; it removes that marker only after a full write. A fresh compiled-helper probe returned `P` for the short write, exit 5 from a new helper, unchanged partial output, and a retained marker. Image source creates the private directory with mode 0750 and configures its absolute path. A full write followed by a lost reply remains ambiguous to the caller: the marker is removed before the `W` reply, so this is not an exactly-once acknowledgement mechanism. The sole setup owner must not retry automatically or claim hosted ingestion.

## Scope and remaining verification

The source uses a single `write(2)` for a complete assembled record and reports `W` only when the returned byte count matches its length; short writes poison the current helper. A BEAM GenServer performs admission before its mailbox with one atomic slot. The wire map uses the documented kind mapping, `id == message`, stable macro source location, and no declaration details; the closed numeric `Details` struct restricts optional context. The SDK does not autoemit setup; its `setup_complete/0` is explicitly called. `choose/1` reads fresh `/dev/urandom` bytes at each attempt and rejects samples above the largest multiple of the choice count. These are source conclusions, with focused local probes only where stated.

The current writer has one BEAM-local GenServer/port per VM. The private native lock now refuses a concurrent second helper rather than providing a shared endpoint. The [BEAM feasibility design](../scratchbook/beam-sdk-feasibility.md) calls for one bounded private writer endpoint when separate OS command processes share a container. Accordingly, the current design is suitable only where one SDK-owning BEAM instance emits per container; a future separate command process in the same container would be refused until it uses that owner's endpoint. The local lock/marker probes do not establish hosted capture or process behavior after a container is recreated with a fresh writable layer. No readback or ingestion acknowledgement exists in the hosted sink.

The current eight SDK unit tests exercise one local writer, local JSONL readback, a synthetic short write and in-VM/helper restarts, delayed acknowledgement, invalid frames, disabled/unavailable status, and choices. They do not prove hosted sink semantics, multi-process output, source catalog completeness across the real workload, the single setup owner, or NixOS/native isolation. The implementation agent reported exit 0 for `mix format --check-formatted`, `mix compile --warnings-as-errors`, `mix test` (8 passed), C `cc -std=c11 -O2 -Wall -Wextra -Werror`, and a direct Dialyzer run against this SDK and Jason beams. I independently compiled the C helper with `-Werror` for the focused probes; I did not independently run the Mix/Dialyzer gates, `mix precommit`, Nix image tests, or a hosted Antithesis run. The pinned `node scripts/check_contracts.mjs list` discovery found the root and `antithesis/CONTRACTS` scopes plus `sdk-admission-before-mailbox`, `sdk-atomic-append`, `sdk-single-explicit-setup`, and `sdk-direct-random-draws`; it is syntax/discovery evidence, not semantic proof. The harness `antithesis-setup-owner` contract names the Python workload bootstrap as the single setup owner; the BEAM SDK exposes the signal but does not call it at startup.

Architecture impact: the SDK introduces a harness-only assertion transport, native helper and private poison state without changing application control authority or the diagnostic custody decision in ADR-0149. ADR-0033's NixOS machine evidence requirement remains separate. The corrected local transport faults no longer block local JSONL evidence; hosted ingestion, complete assertion coverage, multi-process topology and native machine acceptance remain unverified. No ADR status or implementation claim changes from this review.
