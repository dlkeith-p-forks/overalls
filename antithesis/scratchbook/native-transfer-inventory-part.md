## Architectural context

- Current authority is ADR-0155, accepted/partial: stopped-only relocation reserves one destination disk footprint and an endpoint slot, probes before stopping a running source, snapshots only after recorded stop, sends one full `lilly-b` stream, performs a fenced handoff, waits for destination readiness, then deletes the origin. Full-stream resume and pre-handoff cancellation restoration remain (`docs/architecture/decisions/0155-stopped-only-relocation.md:41-89,126-142`). Older precopy/baseline-incremental narrative does not describe this check's current full-stream source.
- ADR-0037 retains the separation between ZFS data and execution authority, pinned SSH endpoints/keys, placement/epoch fencing and independent-host relocation acceptance (`docs/architecture/decisions/0037-workload-placement-and-relocation.md:28-33,66-128,159-174`). Its own native transfer evidence explicitly scopes the fixture to one machine/two pools and excludes orchestration/SSH (`0037:420-445`).
- ADR-0072 requires every profile-derived drive in the placement dataset, exact drive-name/size validation and publication under destination ownership (`docs/architecture/decisions/0072-multi-disk-workload-transfer.md:41-70`). Current two-drive fixture assertions cover storage-side shape/content/publication, while fleet Inception relocation/clone acceptance remains a separate obligation (`0072:96-108,151-154`).
- ADR-0035 retains sparse guest disks, LZ4, no reservations/refreservation, native GUID ownership and physical/logical accounting; implemented backend selection is explicitly separate from physical-host rollout (`docs/architecture/decisions/0035-zfs-only-provisioning.md:20-25,67-114`). ADR-0071 makes transfer-service configuration/enrollment mandatory but distinguishes it from working peer connectivity/evacuation (`docs/architecture/decisions/0071-required-lilly-transfer.md:18-65`).
- ADR-0033 says even two Lilly QEMU nodes share one physical failure domain and do not prove independent-host resilience or throughput (`docs/architecture/decisions/0033-nixos-machine-verification.md:75-80`). The inspected single-node check has a narrower boundary.

## Native stream and receive assertions

- Source and snapshot GUIDs are read and required to be positive numeric values (`driver.py:52-65`). Receive command binds destination policy: unmounted, no-auto-mount, read-only, lz4, no reservations, `exec/setuid/devices=off`, and destination-only host marker (`driver.py:66-71`).
- Interrupted full stream: pipe `zfs send source/workload@lilly-b` through `head -c 4194304` to `zfs receive -s`; require a nonempty resume token, unmounted staging and no snapshot until resumed (`driver.py:73-82`). Resume with `zfs send -t`; require token cleared, exact snapshot GUID lineage, destination filesystem GUID distinct from source, unmounted/read-only policy and destination host marker (`driver.py:83-95`).
- Independent full receive into `target/fallback` must have a fresh destination filesystem GUID, preserve snapshot GUID, mount successfully, and produce the expected ext4 hash (`driver.py:96-114`).
- Aborted receive must leave a token, `zfs receive -A` must remove only staging, and source/destination GUIDs must remain unchanged (`driver.py:116-125`). Production native helper is run for normal and caller-EOF cancellation paths; both received datasets are mounted only after policy change, hashed against source, and destroyed (`driver.py:127-133`; helper implementation `stream.py:47-82,101-132`).
- `stream.py` validates production resume-token semantics: exact snapshot name/GUID and zero parent GUID are accepted; altered name, GUID, parent GUID or checksum is rejected with empty stdout/stderr (`stream.py:26-45`). It invokes `lilly-transfer-stream` with a 30,000 ms bound and lock path, echoes a nonce without leaking payload, expects status 0 or 4 for EOF interruption, and requires no trailing output (`stream.py:47-82`). Normal and interrupted native sends verify target token cleared, unmounted/read-only datasets and matching snapshot GUIDs (`stream.py:115-132`).
- Destination-local staging journal/ownership checks cover idempotent prepare/verify, orphan marker refusal, exact dataset GUID binding, policy-bit refusal (`readonly`, `canmount`, `exec`, `setuid`, `devices`), foreign nonce refusal, foreign snapshot refusal, bound snapshot/filesystem substitution refusal, replacement GUID handling, and cleanup without active placement (`driver.py:135-210`). `received.exs` requires stream state `received`, destination GUID unlike source, no active ownership marker, and staging unavailable to allocation (`received.exs:211-230`).
- Partial receive path requires a resume token, stable interrupted GUID, wrong-nonce and wrong-policy resume refusals, journal transition to `retiring`, then retired journal with the same GUID and no source damage (`driver.py:212-266`; `receive.py:67-73`).

## Adoption and crash-recovery assertions

- Adoption fixture uses real ZFS and production disk adoption, but synthetic seven-byte kernel/initrd/boot fixtures; its contract limits evidence to storage/adoption, not guest boot (`adoption.exs:1-4,38-67`). Root adoption verifies native staging, destination journal and claim creation, then kills a systemd-wrapped adoption after committed native `destroy`, `mount`, and `set` operations. For each interruption it requires legal durable claim state, original dataset GUID, retry idempotence, foreign nonce refusal, read-only/mount policy, and eventual ready state/content hash (`driver.py:268-355`; kill wait at `driver.py:299-307`).
- Two-drive inception adoption creates a 2 GiB `rootfs.ext4` and 256 GiB sparse `data.raw` (8 MiB random prefix), checks missing/renamed and wrong-sized drive refusal, then checks exact file set, hashes, size, owner UID 1196615/mode 600 and no blank-completion after a retained drive is removed (`driver.py:360-450`). This remains same-VM ZFS/filesystem evidence.
- Hegel state machine chooses prepare/verify/adopt/retry/reuse/cancel/cleanup operations with explicit assumptions (`driver.py:709-925`). `claim_states_are_legal` and `dataset_guids_stable` are `always=True` invariants (`driver.py:926-950`); `foreign_nonce_still_rejected` and `received_policy_bits` are sampled invariants (the Hegel decorator says non-`always` invariants are sampled at 1/step count, while initial/final states are always checked: `nix/verification/hegel/python/hegel/statemachine.py:70-80`). The latter enforce foreign nonce rejection and staged/ready readonly/canmount/exec/setuid/devices policy (`driver.py:951-985`).
- Crash/replay cleanup is in-VM: setup/teardown kills units, resets placement journals and removes fixture-local keys; this proves replay against a restored fixture baseline, not host loss or cross-host recovery (`driver.py:546-651`).
- Final retention check mounts the received rootfs read-only, verifies `phase=final` and 24 MiB data, destroys only source snapshot/workload, confirms source neighbor and authority remain, then changes the destination copy to writable, writes an `activation` marker inside the ext4 filesystem and preserves destination GUID (`driver.py:989-1016`).

- Native stream child waits: 5 s for initial nonce, 10 s marker deadline, 35 s completion, 5 s cleanup wait; slow-send fixture sleeps 60 s awaiting revocation (`stream.py:59-81,101-114`).

## Physical-boundary gap and reporting rule

The check gives meaningful native ZFS evidence: two block-backed pools, real `zfs send/receive`, real interrupted/resumed receive tokens, snapshot GUID lineage, ext4 hashing/content and production Lilly native helpers. It does **not** establish independent-host availability, host/network/SSH/TLS authentication, Marshall/Oban orchestration, source-stop/readiness receipts, Firecracker guest boot, physical host failure domains, or multi-host capacity. A single VM owns both source and target disks and can inspect/mutate both directly. Historical documentation records a stopped-only `zfs-transfer` pass, but the stopped-only review explicitly says those checks/results were from incoming `d4499c4c` before durable-identity integration and are not executions of the combined tree (`docs/architecture/reviews/2026-10-10-stopped-only-relocation.md:14-19,107-121`). Report any current result as **native storage/transfer fixture evidence only**; retain independent physical-host and full relocation acceptance as open obligations.
