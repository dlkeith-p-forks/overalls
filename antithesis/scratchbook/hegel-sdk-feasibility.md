Read-only research, 2026-10-13. Repository: `/home/ghuntley/src/overalls-antithesis-reset`, observed HEAD `9fe1e493b2090d44bacd16089049cd12b316d58a`. ## Conclusion

The existing native Hegel engine can emit correct Antithesis assertion records. The Python adapter currently prevents that integration by omitting test locations. It also explicitly defaults to `ci`, which selects a deterministic PRNG in its newer engine, rather than Antithesis-controlled entropy on every draw. Separately, the repository's older Rust `hegeltest` dependencies need their `antithesis` feature enabled before execution inside Antithesis. None of these assertion changes establishes coverage instrumentation or native VM isolation.

The smallest correct hosted path is a Python worker that uses the existing C engine with `profile="workload"`, preserves the profile's health-check settings, supplies one stable typed test location per property for generation and replay, and registers the complete expected property catalog before execution through the official Python SDK. Keep the ordinary NixOS machine checks and their physical-acceptance requirements. Build separate instrumented Rust/Hegel artifacts and package symbols if hosted native coverage is required; SDK installation alone is insufficient.

## Minimal implementation plan

1. **Define a typed per-property identity.** Add a frozen `TestLocation` record with source file, uint32-bounded begin line, class/module scope and function name. Validate line range and strings before crossing the C ABI. Store it on both `Property` and `StatefulProperty`; use stable qualified names, never generated values or credentials. Keep the location and assertion ID the same across runs and replays. Build a separate config per unit using this identity; assign the matching `database_key` when local CI needs per-test deterministic seeds.
2. **Expose the native setter with its actual ABI.** Bind `hegel_settings_set_test_location(ctx, settings, file, begin_line, class_name, function) -> hegel_result_t`; ctypes argument types are `[c_void_p, c_void_p, c_char_p, c_uint32, c_char_p, c_char_p]` with `c_int` return. Call it during `EngineConfig.build`, before both `hegel_run_start` and `hegel_test_case_from_blob`. The [header at line 925](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/hegel/hegel.h:925) and [implementation at line 1268](/nix/store/svkwnqz7xb0w701fzp8kgn93dmgxsgj3-source/hegel-c/src/lib.rs:1268) agree. The implementation copies UTF-8 strings, so no long-lived borrowed string retention is required after a successful setter call.
3. **Make hosted profile selection explicit.** The new hosted runner passes `profile="workload"`, with no fixed seed/derandomization and a disabled example database. Change health-check overrides to `tuple[str, ...] | None`; `None` leaves the profile unchanged, while an explicit tuple applies the requested mask, including the empty mask. Retain the ordinary NixOS checks' existing explicit CI settings. An environment-aware default can subsequently choose `None`, but is unnecessary if the hosted runner selects the correct profile explicitly.
4. **Declare expected properties before evaluating them.** Pin the official Python `antithesis` SDK in the hosted worker's Nix closure. Use the documented `assertions.assert_raw` adapter API with explicit location and `hit=False`, or the newer typed `catalog.Assertion`/`catalog.SourceLocation` with `catalog.register()`, to enumerate registered property declarations before any test runs. Match the native engine's exact assertion ID/message/type/location. SDK API availability must be verified against the version actually pinned; the current docs do not identify the introduction version of the newer catalog API. Avoid duplicate evaluations: leave property verdict emission with the native engine, and use official SDK assertions for worker lifecycle, required operation reachability and workload-level oracles. An explicit startup roster also exposes missing registrations.
5. **Use SDK randomness for non-Hegel choices.** Use official Python randomness for selecting scenarios, roles, operation targets and fault schedules outside Hegel. Hegel input choices remain engine-driven through its urandom backend. Do not seed a second PRNG from SDK outputs or cache them for later decisions. Keep mutable oracle/checkpoint state outside `ANTITHESIS_OUTPUT_DIR`; it is an output sink whose writes cannot be read back in the hosted environment.
6. **Keep driver interfaces typed and execution claims scoped.** The new worker should depend on explicit protocols and structured request/result/state records, with validated JSON entering as `object` and narrowing into domain types. A typed HTTP/container-control adapter must distinguish transport failure, refused operation, committed result and absent state. Do not fabricate success from missing data. Preserve bounded waits and observable resource ownership/fences. The four existing machine scripts rely on Nix-injected machine globals and setup; an SDK-enabled Python package does not make those whole-machine tests directly runnable in Antithesis.

For Nix driver location mapping, functions currently execute as `<string>`. The installed Python 3.13 upstream driver [loads `config.test_script`](/nix/store/f6ji09lhm3788i0mig2l5z6yppn6grpm-nixos-test-driver-1.1/lib/python3.13/site-packages/test_driver/driver.py:151), [injects `driver`](/nix/store/f6ji09lhm3788i0mig2l5z6yppn6grpm-nixos-test-driver-1.1/lib/python3.13/site-packages/test_driver/driver.py:312) and [executes the string](/nix/store/f6ji09lhm3788i0mig2l5z6yppn6grpm-nixos-test-driver-1.1/lib/python3.13/site-packages/test_driver/driver.py:387). A minimal optional composer extension can pass `source_file=str(driver.config.test_script)` and stable scope from the Nix test name; the function's code first line then refers to the generated composed script. State-machine class locations need explicit registration metadata or a reviewed class-definition capture; `inspect.getsource(cls)` is not reliable for an exec-defined class. Validate generated-file line mapping against a built driver before claiming original-file locations. Hosted Python files can use their real code filenames directly.

### Repair and enforce the Python ABI typing

The existing [_lib.Lib.__getattr__](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/hegel/python/hegel/_lib.py:344) exposes every native symbol as `Callable[..., int]`; it does not give the checker symbol-specific argument contracts. Use finite, typed wrapper methods for the ABI calls used by engine/generators/state-machine code, keeping dynamic ctypes results behind an `object` boundary with runtime validation. Every handle output must be checked nonnull before converting to an integer. Specify pointer arguments and callback inputs using actual ABI pointer types or an equivalent pointer-compatible callback declaration, instead of arbitrary `object` sent to `string_at`. Preserve registered runtime `restype`/`argtypes` as well as Python interface types; they address different failure modes.

The exact scoped command `ty check -c 'src.include = ["nix/verification/hegel/python"]' nix/verification/hegel/python --python-version 3.13 --output-format concise` finds nine errors:

- `engine.py:261`: `string_at` receives an arbitrary `object` rather than a pointer-compatible type.
- `engine.py:297`: `_failure_list` expects an `int` but receives `c_void_p`.
- `engine.py:334`: replay converts a nullable pointer value to `int` without narrowing.
- `runner.py:41`: a generic callable is treated as a named Python function.
- `statemachine.py:58,60,78,79`: generic callable types do not support decorator attributes or `__name__`; existing `type: ignore` comments use another checker's diagnostic spelling.
- `statemachine.py:138`: `Pool.draw[T]` returns an arbitrary object as unrestricted `T`.

Use named-function protocols with precise `__name__`/`__qualname__`/code metadata, keep decorator metadata in typed registries rather than arbitrary function attributes, and make pools generic over their stored values. Remove unrestricted `Any` in rule/invariant signatures at [statemachine.py:14](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/hegel/python/hegel/statemachine.py:14). Add `nix/verification/hegel` and the new worker to the explicit root `ty` scope, and include a targeted binding type check in its Nix package gate. The binding [advertises Python >=3.11](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/hegel/python/pyproject.toml:9), but [uses Python 3.12 type-parameter syntax](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/hegel/python/hegel/generators.py:39); align that metadata with the repository's selected Python 3.13 runtime.

## Coverage and symbols are separate work

The ordinary [libhegel build](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/hegel/libhegel.nix:18) only requests `-p hegeltest-c`, disables engine tests and copies normal release libraries. The existing exact library exposes the location symbol, but its saved ELF/symbol inspections show no `__sancov_guards`, `__sancov_pcs`, `antithesis_load_libvoidstar` or DWARF debug sections. It is not evidence of an instrumented Hegel build.

The official [Rust instrumentation guide](https://antithesis.com/docs/reference/sdk/rust/instrumentation/) currently requires `antithesis-instrumentation = "0.1"`, a source reference `use antithesis_instrumentation as _;`, and, for the documented non-LTO GNU/Linux target, these flags:

```text
target = x86_64-unknown-linux-gnu
-Ccodegen-units=1
-Cpasses=sancov-module
-Cllvm-args=-sanitizer-coverage-level=3
-Cllvm-args=-sanitizer-coverage-trace-pc-guard
-Cllvm-args=-sanitizer-coverage-pc-table
-Clink-args=-Wl,--build-id
```

Add a separate pinned hosted Hegel derivation with the instrumentation crate retained by the final artifact, matching vendor hash, preserved debug information and GNU build ID. This is a real source/dependency/build change, not a flag applied to the existing binary. Hegel's C crate is `no_std` internally, so verify the instrumentation crate's compatibility with the default `std` artifact build; do not infer it from the SDK docs. Check the actual `.so` loaded by Python, not just an unrelated executable. The official validation page requires the `antithesis_load_libvoidstar` text symbol and the two sanitizer-coverage ELF sections; also confirm symbols after Nix install/strip stages. Include unstripped modules, or corresponding separate debug information, under `/symbols` in the same container image. Final hosted validation requires passing `Software was instrumented` and `Every instrumented module has symbols` for the modules intended to be covered, with Hegel explicitly observed.

For native SUT helpers and retained Rust property binaries, provide separate GNU/Linux hosted targets. Existing helpers often use `lto=true` and `strip=true`, for example [host-lock](/home/ghuntley/src/overalls-antithesis-reset/lilly/native/host-lock/Cargo.toml:14); [terminald production](/home/ghuntley/src/overalls-antithesis-reset/nix/domains/artifacts/infrastructure/terminald.nix:2) builds through `pkgsStatic`. Use the official link-time LTO instrumentation scheme or explicitly turn LTO off for the hosted profile, and preserve symbols. Do not assume the documented GNU/Linux recipe works unchanged for static musl or macOS artifacts.

The [Python SDK docs](https://antithesis.com/docs/reference/sdk/python/) explicitly say Python assertion cataloging does not provide Python coverage instrumentation. SDK assertions and Python-generated inputs therefore establish neither Python code coverage nor native Hegel/SUT coverage.

The proposed change affects verification interfaces and adds a significant test dependency/build variant: use architecture-review and hldd-maintenance during implementation, update the testing documentation/HLDD evidence and affected ADR evidence, and keep ADR-0017 accepted/partial until its actual physical requirements are met. Relevant requirements are [ADR-0002 types and validation](/home/ghuntley/src/overalls-antithesis-reset/docs/architecture/decisions/0002-elixir-ash-and-types.md:19), [ADR-0028 contract review](/home/ghuntley/src/overalls-antithesis-reset/docs/architecture/decisions/0028-colocated-code-contracts.md:41), and [ADR-0033's inherited machine verification](/home/ghuntley/src/overalls-antithesis-reset/docs/architecture/decisions/0033-nixos-machine-verification.md:24), carried through [ADR-0043](/home/ghuntley/src/overalls-antithesis-reset/docs/architecture/decisions/0043-declarative-host-provisioning.md:25) and later replacements. [ADR-0017](/home/ghuntley/src/overalls-antithesis-reset/docs/architecture/decisions/0017-durable-vm-actors-and-host-ownership.md:21) requires root/systemd/cgroup-v2 ownership and real KVM readiness; an adapted hosted driver cannot silently weaken those production contracts.

Reviewed applicable contracts include root `repository-decision-evidence`, `repository-secret-diagnostics`, `repository-contract-maintenance` and `repository-test-claim-boundary`; `nix/CONTRACTS` pinned inputs; `nix/verification/tests/CONTRACTS` actual source-built packages/local fixtures; `nix/verification/tests/support/CONTRACTS` composed static drivers; and the Hegel local engine-pin, binding-match, package-set and property-execution contracts. The report surfaces pre-existing typing and missing-hosted-integration gaps without weakening those requirements. Preserve secret-custody redaction at [secret-custody/default.nix:36](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/secret-custody/default.nix:36): property/catalog metadata must never include drawn secret values, exception payloads or reproduction blobs.

## Official documentation consulted

- [Rust SDK](https://antithesis.com/docs/reference/sdk/rust/): call `antithesis_init()` early; assertion/catalog features and local `ANTITHESIS_SDK_LOCAL_OUTPUT` are distinct from instrumentation. A no-default-feature SDK build disables assertions/lifecycle and has an empty assertion catalog.
- [Rust instrumentation](https://antithesis.com/docs/reference/sdk/rust/instrumentation/): instrumentation crate, non-LTO versus LTO flags, symbol/ELF checks and `/symbols` packaging.
- [Python SDK](https://antithesis.com/docs/reference/sdk/python/): Python >=3.9; static assertion cataloging, literal-message limits, local catalog workflow and explicit absence of Python coverage instrumentation.
- [Python adapter API](https://antithesis.com/docs/generated/sdk/python/antithesis/assertions.html#assert_raw) and [typed runtime catalog API](https://antithesis.com/docs/generated/sdk/python/antithesis/catalog.html): third-party framework declaration/evaluation APIs with explicit locations; runtime registration handles dynamically generated property messages.
- [Fallback assertion contract](https://antithesis.com/docs/reference/sdk/fallback/assert/) and [fallback SDK](https://antithesis.com/docs/reference/sdk/fallback/): declaration/evaluation identity and atomic newline-terminated JSONL output contract.
- [Randomness API](https://antithesis.com/docs/reference/sdk/generate_randomness/): use returned randomness directly, without secondary PRNG expansion.
- [Antithesis environment](https://antithesis.com/docs/configuration/the_antithesis_environment/): captured output sink, no external connectivity, simulated x86-64 and no nested hardware virtualization.
- [Coverage and symbolization](https://antithesis.com/docs/product/writing_tests/instrumentation/coverage_instrumentation/): instrumented-module recognition and symbolization evidence, including Hegel.
