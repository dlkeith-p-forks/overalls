## Decision and evidence boundary

A fresh **single NixOS Linux VM under QEMU TCG**, with **2 GiB guest RAM, one vCPU, a 128 MiB ZFS ARC cap, and two sparse 1 GiB mirrored data disks**, is a credible small test target for real Linux ZFS, nftables, transparent sockets, packaged Brady, and native Lilly storage helpers. It has not been built or booted in this review. The closest repository fixture already places source-built Brady, actual Lilly-generated nftables, three veth clients, a local HTTP/TLS origin, and real ZFS in one 2 GiB router: [brady-network/default.nix:17](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/brady-network/default.nix:17), [driver.py:4](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/brady-network/driver.py:4), [storage.py:1](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/brady-network/storage.py:1).

This is **new emulated Linux integration evidence**, not native Firecracker execution, guest boot trust, physical isolation, independent-host recovery, disk hardware durability, or physical HA. Existing machine gates remain mandatory. In particular, the shared ZFS node's `zfs-machine-requires-kvm` contract requires failure without KVM and explicitly says software emulation is not acceptance: [zfs-node.nix:11](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/support/zfs-node.nix:11). Make a separate derivation; do not relax or alias that gate. The Brady fixture similarly excludes authoritative attribution and Firecracker evidence, and the transfer fixture excludes orchestration, SSH, readiness and independent physical hosts: [driver.py:4](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/brady-network/driver.py:4), [zfs-transfer/CONTRACTS:1](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/zfs-transfer/CONTRACTS:1).

Affected architectural requirements are the sparse/GUID/flush policies inherited from ADR-0031 and ADR-0035; the machine-evidence boundaries inherited from ADR-0033; Brady custody/isolation/attribution from ADR-0069, carried forward by ADR-0135 and ADR-0140; current state-only journal/control boundaries from ADR-0149; independent same-pool copies under ADR-0145; stopped single-snapshot transfer under ADR-0155. The source-only research changes no decision. Implementation would add a documented verification scope and must reconcile architecture/HLDD/scenario coverage in its own change.

### Boot sequence and trusted control paths

1. The outer supervisor opens an exclusively owned VM state directory; validates its manifest, image/kernel/initrd hashes, disk identities and sizes; starts exactly one QEMU child with the retained disk paths. QMP lives in a root-only local Unix socket, for example `/run/routervm/qmp.sock`. Give QMP command IDs and retain command reply/event correlation. Do not expose QMP on the container network.

An empty owned initial state may create `tank`; an existing pool is imported by its recorded GUID and inspected, never replaced with unconditional `zpool create -f`. Creation in the existing driver is appropriate because Nix-test disks are disposable; it is not a reboot custody policy.
3. Create/verify `tank/lilly`, persist actual zpool/dataset GUID bindings, run unchanged Brady preparation, apply/read back 256/64 MiB fixture quotas. Runtime JSON contains the actual identity and absolute pinned `zfs`/`zpool` paths, following the current helper input shape ([storage.py:10](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/brady-network/storage.py:10)).

## Persistent disk custody and crash semantics

Use a distinct outer directory such as `/var/lib/routervm/state/<fixture-id>/` containing the root overlay, `mirror-a.raw`, `mirror-b.raw`, and a private manifest. The exact persistence mechanism across Antithesis/container recreation still requires deployment validation; the repository supplies no evidence for a particular volume feature. Ordinary supervisor or QEMU restart must reopen the same files, never truncate/copy the initial blank disks over them. One process owns them at a time. Boot failure retains the directory for diagnosis. Reset to an empty timeline is an explicit harness action on its own fixture directory, after child termination, not normal restart behavior.

Persist guest storage control journals with the data they govern, not only under ephemeral `/run`: `/pool/.lilly-zfs/active/<placement>/claim.json`, received/import records, native ownership nonce and tombstone state must survive guest reboot when those paths are exercised. Source and neighbor markers belong in independently inspectable datasets; refusal checks compare their actual GUID/content before and after. The established fixture custody rule is recorded GUID, mount and owner before nonrecursive destruction; failures retain state ([zfs_fixture.exs:4](/home/ghuntley/src/overalls-antithesis-reset/lilly/scripts/zfs_fixture.exs:4), [zfs_fixture.exs:58](/home/ghuntley/src/overalls-antithesis-reset/lilly/scripts/zfs_fixture.exs:58)). Whole disposable-pool teardown is a separate trusted harness operation after verifying it owns both attached disk files; it must never reuse application cleanup authority.

Prefer raw mirror files and an explicit QEMU flush-respecting backend, initially `cache=none` if direct I/O is supported by the actual state filesystem. The hosted Antithesis container filesystem refuses O_DIRECT (run `bbb308949ab76c0f1ce04fd209f1f091-65-0`), so the runners probe it and fall back to flush-respecting `cache=writeback`, printing the effective mode. Validate that support and capture the effective flags; fail the relevant durability case if the backend cannot honor the chosen semantics. Do not use `cache=unsafe`, implicit write-cache defaults or discard as proof of reclamation. The inherited storage requirement distinguishes acknowledged guest flushes from unflushed writes and preserves ZFS `sync=standard` ([ADR-0031:130](/home/ghuntley/src/overalls-antithesis-reset/docs/architecture/decisions/0031-sparse-zfs-storage-and-capacity.md:130)). This QEMU backend is a proposed test design, not an existing source-verified export.

A QMP `system_powerdown` is a graceful shutdown request. QMP reset is an abrupt guest restart; killing QEMU is emulator process loss. Neither necessarily clears outer OS/filesystem caches. They establish only their recorded fault class. Acknowledged `fsync` markers surviving those operations can support emulated guest/process-crash persistence, not power-cut durability of physical media. Perform oracle reads after a fresh guest boot/import using the same files; never substitute an in-memory pre-crash response or a cached driver variable for the post-crash observation.

## Image, kernel and closure delivery

Create a **fresh locked NixOS configuration/package** for this VM using the stable `nixpkgs` host/test input and the source-built application packages from `buildNixpkgs`. The repository deliberately keeps those inputs separate ([flake.nix:24](/home/ghuntley/src/overalls-antithesis-reset/flake.nix:24), [flake.nix:113](/home/ghuntley/src/overalls-antithesis-reset/flake.nix:113), [nix/verification/tests/catalog.nix:3](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/catalog.nix:3)). Required kernel/initrd modules include virtio root/data/control, ZFS, nftables/conntrack/TPROXY and the chosen namespace interfaces. Use direct kernel/initrd boot for this harness; it does not establish EFI/mirrored system boot ([ADR-0033:57](/home/ghuntley/src/overalls-antithesis-reset/docs/architecture/decisions/0033-nixos-machine-verification.md:57)).

Export one immutable artifact manifest retaining Nix references to the exact system toplevel, matching kernel/initrd/modules, base root image, QEMU binary, Lilly/Brady/hostTools and controller executables. A root image containing a module package from another kernel is invalid even when `zfs` userspace exists. After build, export/query the **complete recursive closure**, rather than copying release scripts or following only their direct symlinks. The repository's closure pattern is `nix-store --query --requisites` followed by `nix-store --export`, checksums and recorded store path ([package_release.sh:13](/home/ghuntley/src/overalls-antithesis-reset/scripts/package_release.sh:13)); Lilly release metadata retains hostTools references ([packages/default.nix:133](/home/ghuntley/src/overalls-antithesis-reset/nix/domains/artifacts/default.nix:133)). That script's current application allowlist excludes Brady, so the new artifact packager should be a separate typed/contracted implementation, not an undocumented reuse of its argument interface.

The outer container includes/imports the closure before runtime, exposes the exact absolute store paths and starts the root image offline. It must not need a Nix daemon, network fetch, production credentials, host ZFS module or privileged outer mount. ZFS privilege lives inside the emulated Linux guest. Build phase checks source/package identity; runtime checks `uname`, loaded ZFS version, host-tools metadata, manifest hashes, actual attached serials/size and the packaged Brady executable. Do not assume a NixOS testing-framework VM script is self-contained: exporting a new closure/boot bundle and validating it offline is a required implementation step. No existing repository output currently supplies this TCG router bundle.

Use independently derived payload digests and native observations; SDK/property output should come from the outer controller after successful guest evidence collection. Include guest boot ID, operation ID, fault class and witness scope in each observation. ### Routing source identity: three distinct claims

1. **Packet source custody can be native inside this VM.** Real veth MAC/source guards and production strict sysctls can prove that packets from one fixture peer cannot impersonate another admitted source in this emulated Linux topology. Keep selected source/MAC/slot values in the workload model; inspect real kernel counter changes and origin results.
2. **Kernel incarnation label custody can also be native.** Add `FlowLabel.rules` for validated synthetic execution identities alongside the source guards; use actual `lilly-flow-label` exact-tuple lookup inside the router namespace. Assert initial unconfirmed SYN labels, unchanged existing connections across rule-generation change, unlabeled established connection refusal and no address-only fallback. Labels incorporate host/placement/epoch/generation and do not grant packet admission ([flow_label.ex:7](/home/ghuntley/src/overalls-antithesis-reset/lilly/lib/lilly/network/flow_label.ex:7), [flow_label.ex:26](/home/ghuntley/src/overalls-antithesis-reset/lilly/lib/lilly/network/flow_label.ex:26), [flow_lookup.ex:8](/home/ghuntley/src/overalls-antithesis-reset/lilly/lib/lilly/network/flow_lookup.ex:8)). The existing small native helper check demonstrates the oracle on loopback and synthetic labels ([evaluation/flow-label.py:36](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/evaluation/flow-label.py:36)); porting it to veth is new evidence.
3. **Authoritative VM/user attribution remains absent without physical execution evidence.** Current `prepare.exs` emits router/guard rules only and starts no attribution server ([prepare.exs:8](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/brady-network/prepare.exs:8)). Brady therefore correctly retains unresolved identity. Production resolution requires exact kernel label + current connected execution view/identical durable intent/unexpired running observation + authenticated owner, then repeats label/version checks within one second ([attribution.ex:5](/home/ghuntley/src/overalls-antithesis-reset/lilly/lib/lilly/network/attribution.ex:5)). An optional synthetic-view/socket subtest may exercise the actual root/Brady peer-credential and closed protocol path, but its successful join remains a synthetic-authority logic test. Do not construct a fake running row and call it native VM-owner proof. Wrong root peer, host mismatch, absent/changed execution, stale owner or timeout must remain unresolved ([brady/attribution.ex:9](/home/ghuntley/src/overalls-antithesis-reset/brady/lib/brady/attribution.ex:9)).

## Fault boundaries

Separate property witness metadata into at least `outer-automatic`, `explicit-guest-process`, `explicit-guest-network`, `explicit-quota`, `explicit-zfs-disk`, and `explicit-qmp` fault classes. The repository does not establish Antithesis platform behavior for nested QEMU, so exact outer injection availability and container-recreation disk custody require separate platform validation.

| Fault class | Actual effect / first implementation | What it must not be called |
| --- | --- | --- |
| Outer automatic faults | Whatever the platform injects at the QEMU/controller container, its processes, outer NIC and backing-file I/O. Record QEMU death/restart and management-channel loss explicitly. | Direct fault injection into individual guest BEAM processes, guest nftables, inner disk members or guest namespace traffic. |
| Explicit guest service faults | Fixed commands to stop/restart/kill Brady, origin or pressure sampler; bounded freeze/thaw where supported. Kill native helper after a reported committed effect. | An outer platform process fault. Guest `systemd` supervised recovery and driver control failure are separate outcomes. |
| Explicit guest network faults | Drop/restore a selected owned namespace link, route or bounded nft fault table; origin connection disruption; wrong source/MAC, QUIC and protected-target histories. | Outer network exploration. All client↔Brady↔origin veth traffic is inside one guest, so outer network loss may touch none of it. |
| Explicit quota/pool pressure | Native `zfs set quota/refquota`, bounded incompressible writes and actual native available-space observations. | A synthetic cache flag or driver-only free-space model. |
| Explicit disk faults | Native `zpool offline/online` one owned mirror member, verify degraded state and resilver, retain/re-read data; later bounded QEMU backend error injection after proving support and recovery. | Physical disk failure or independent power domain. Production native inventory refuses degraded backing rather than inventing capacity ([native-zfs/driver.py:259](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/native-zfs/driver.py:259)). |
| Explicit QMP faults | Correlated stop/cont, guest reset, graceful powerdown, or controlled QEMU termination/restart while retaining files. Hot-unplug/replug and block-error commands are optional later work after validating their protocol/support. | Automatic guest process faults, physical power loss, or disk hardware durability. Reset and process loss need distinct witness classes. |

Fault application and fault removal must be separately acknowledged; restoration failure cannot silently start a “quiet” liveness window. Use actual `zpool status`, service/boot IDs, link/rule inspection and QMP events to prove the intended state. Assertions that need a recovery opportunity should state which controls must be healthy; safety refusal/orphan/custody checks remain meaningful during faults. Avoid resetting the whole guest after each command: sustained histories and retained native state are the value of this topology.

## Practical costs and readiness expectations

No TCG boot time, closure size, memory peak or operation rate has been measured. An initial **engineering budget** is several minutes for cold boot/import/namespace/TLS setup (start with a 5–10 minute host readiness watchdog), then seconds-to-tens-of-seconds for small native operations, subject to measurement. This is a proposed timeout budget, not a prediction or evidence. Preserve production internal freshness/attribution deadlines even when the outer watchdog is generous.

The source gives reasons to start small: existing two-CPU KVM router uses 4-second curl and 30–45-second readiness waits ([driver.py:51](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/brady-network/driver.py:51)); native cache pressure queries run each second and expire after three seconds ([storage.py:267](/home/ghuntley/src/overalls-antithesis-reset/nix/domains/system/brady/storage.py:267), [pressure.ex:64](/home/ghuntley/src/overalls-antithesis-reset/brady/lib/brady/cache/pressure.ex:64)). One-vCPU TCG may fail to obtain fresh pressure under concurrent hashing/TLS/writes. That is a measured feasibility limit to diagnose; do not solve it by weakening the production deadline. If full fresh-cache coverage is unreachable, use sequential bounded operations, record the gap and consider a separately approved resource increase.

Reserve outer memory above the 2 GiB guest allocation for QEMU translated-code buffers, the controller, libraries and artifact handling; **roughly 3 GiB outer memory is an initial sizing allowance**, to replace with measured RSS. Two raw sparse 1 GiB mirror files have 2 GiB apparent total; a mirror writes roughly twice the physical stored data plus metadata to outer storage. Empty sparse files are cheap; filling the pool can materialize close to both full disk sizes. The immutable NixOS image/closure and root overlay are additional costs and have no known size from this review. Keep them out of the 256/64 MiB SUT quotas. Export/compress a blank disk recipe rather than full zero-filled data disks.

Do not port the large Brady matrix first: it uses two 512 GiB sparse disks and multi-GiB bodies ([default.nix:24](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/brady-network/default.nix:24), [large-storage.py:256](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/brady-network/large-storage.py:256)). Do not port the full Firecracker clone/lifecycle matrix either: it requests nested KVM, 4 GiB RAM and two 8 GiB disks ([zfs-guest/default.nix:5](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/zfs-guest/default.nix:5)); recorded existing native runs took 1641 seconds for clone and 3625 seconds for lifecycle ([ADR-0143:137](/home/ghuntley/src/overalls-antithesis-reset/docs/architecture/decisions/0143-faster-create-clone-delete.md:137)). Those figures are historical KVM/native scope and cannot be multiplied into a reliable TCG estimate.

## Implementation stages and acceptance criteria

1. **Fresh build/boot artifact.** Add a new TCG VM derivation and typed outer supervisor/guest command schema with ownership contracts. Export the exact kernel/root/modules/runtime closure and hashes; prove offline boot, one vCPU, 2 GiB RAM, 128 MiB ARC, correct disk serials and no KVM requirement. Preserve every existing native gate unchanged. Capture actual artifact size, boot duration and memory.
2. **Native storage smoke.** First boot creates owned mirror; second boot imports the same GUID without destructive setup. Verify actual 256 MiB parent/64 MiB cache quotas, helper custody refusal, sparse/compressed/random growth, one acknowledged marker surviving graceful reboot and abrupt guest/emulator restart. Positive witnesses must occur before running many negative histories.
3. **Native router/Brady smoke.** Install production validated policies/routes/sysctls; enable veth peers and isolated origin. Verify HTTP, trusted intercepted TLS, TLS distrust/wrong SNI refusal, protected/Customer/lateral/spoofing refusals, QUIC fallback and proxy-stop failure without direct origin reachability. Record which root/router/guard paths are real.
4. **Cache lifecycle and pressure.** Prove one actual public object publication, cross-peer hit, restart/origin-loss hit, guest-reboot read, abandoned/private/authenticated nonpublication, quota shrink, stale sample and invalid custody, parent/pool hysteresis. Record actual pressure freshness percentiles and any CPU contention before expanding concurrent operations.
5. **Small production storage effects.** Re-express interrupted full receive/resume/adoption/retirement against small ext4 files, independent GUID/content/source-neighbor oracles and foreign nonce/snapshot refusal. Add same-pool block-copy only if native offload support and journal identity are verified. Keep separate-pool, real guest-console, readiness and SSH claims open.
6. **Persistent fault histories.** Add explicit guest service/link/quota/disk/QMP actions and record acknowledgments. Exercise restart after committed-effect-before-reply faults and replay with unchanged identity. Integrate outer SDK assertions with validated guest witness evidence and classify outer automatic faults separately. Validate actual platform snapshot/recreation behavior before interpreting a remote run.
7. **Review and verification.** Architecture/HLDD/scenario documents must state this new scope, requirements and remaining native gaps. Run relevant type/static/contract/Nix-evaluation gates, local TCG smoke, meaningful property oracles and mutation probes; then the explicitly authorized remote validation. A passing TCG smoke is not a passing native machine gate. Report actual execution and failures separately from this source feasibility analysis.

The first milestones have concrete blocking questions to resolve by implementation, rather than by speculation: can the chosen exported NixOS root boot offline under TCG; can one vCPU sustain the unchanged three-second native pressure proof; does the outer state filesystem honor the selected QEMU flush mode; and does the actual platform preserve the inner QEMU/disk state at its fault/branch boundaries. No broad builds/tests were run to answer them in this task.

Contract discovery also found a wording conflict that matters if the block-copy helper integration is changed: `image-helper-no-elevation-or-raw-diagnostics` still says operational events use the “durable lifecycle audit” ([image-copy/CONTRACTS:1](/home/ghuntley/src/overalls-antithesis-reset/lilly/native/image-copy/CONTRACTS:1)), while ADR-0149 replaces authoritative journal diagnostics with independent observability ([ADR-0149:37](/home/ghuntley/src/overalls-antithesis-reset/docs/architecture/decisions/0149-independent-observability.md:37)). Reconcile that obligation against current helper/caller behavior during implementation; do not reintroduce diagnostic ACK authority or silently weaken the contract.
