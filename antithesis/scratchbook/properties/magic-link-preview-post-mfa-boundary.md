# magic-link-preview-post-mfa-boundary — Magic-link preview and pending MFA cannot grant browser work authority

**Type / priority / confidence:** Safety (`Always`), P0, high confidence in the intended contract and source locations; unimplemented Antithesis candidate. **Planned primary literal message:** **"Magic-link preview and pending MFA cannot grant browser work authority"**. This message is absent from the fresh `existing-assertions.md` scan.

**Property and assertion semantics.** For one valid SMTP-accepted magic link, a plain HTTP GET, including repeated scanner-style previews, must leave its stored `magic_link` token usable and issue no stored `user` login, session cookie, remember credential or authorized work. A real CSRF-protected POST may consume the link once and create a stored login; replay must not create another. If the account has MFA enabled, [ADR-0160](../../../docs/architecture/decisions/0160-privileged-administrator-step-up.md) makes that new login an ordinary signed-in session: protected reads such as `/overview` are served, but it cannot commit a privileged mutation (passkey credential change or administrator action) until a passkey ceremony for that *same login* commits, and an ordinary read never verifies or elevates it. The earlier wording here, which expected the protected read itself to redirect to Security, came from the superseded ADR-0123/ADR-0131 read-boundary policy. Hosted runs `71f581b61dd448c981377cae8a9624a8-65-0` (old predicate, 29/29) and `73ed4620517cc077e3245020c553077d-65-0` (ADR-0160 predicate, 158/158) both failed for a harness reason instead: the copied session cookie was pinned to the bare host `marshall-b`, which Python's cookie jar never sends to a dotless host (it matches `marshall-b.local`), so replica B saw an anonymous request and redirected to `/sign-in`. `access/http.py` `_pinned` now uses the effective request host; no Marshall defect was involved. With the cookie delivered, run `986e8c81e5e7beeeffe83071f48acd55-65-0` still failed 62/62 for a second harness reason: Phoenix renders `data-phx-main` as a bare boolean attribute, which `HTMLParser` reports as `None`, so `parse_live_page` never found the LiveView root (the unit fixture used `="true"`). The parser now tests attribute presence. Magic links minted by the other replica's Oban node are also accepted, since the token is valid on either replica. `Always` evaluates the before-POST and pending-MFA forbidden-effect inventory after each definite operation; a separate `Reachable` can mark a real accepted POST and a separate `Sometimes` can mark successful same-login verification. Those auxiliary messages must be unique if implemented. Do not require a JS browser visit to remain on the GET page: the real page auto-submits. Use a JS-disabled HTTP/client preview to isolate GET and a JS-enabled browser for the normal journey.

**Fault history.** Request a link through public HTTP, wait for the independently recorded local SMTP DATA acceptance, and extract that exact fixture-owned link. Repeat GETs on Marshall A while delaying SMTP DATA ACK or Oban worker commit; inventory `tokens`, `account_auth_emails`, `users` and browser cookies. POST through A with the actual CSRF form while B races a duplicate POST and A loses its response or restarts. Reconcile by token JTI and user-purpose login rows before classifying an uncertain reply. For an enrolled account, read `/overview` through B before MFA (expected 200 with no verification or new login), attempt a privileged mutation through B (expected refusal or step-up with no stored effect), then complete one real WebAuthn ceremony for the same login. A wrong-session, expired or replayed ceremony must not unlock the other login. A no-MFA account is a separate positive branch; its post-POST access is expected and must not be called a pending-MFA violation.

**Independent oracle.** The SMTP fixture records immutable recipient, Message-ID, accepted DATA bytes and accept/ACK phase; it establishes upstream acceptance, not inbox delivery. A read-only PostgreSQL observer counts exact token purposes/JTIs, verification rows and admitted VM request key/operation rows. The browser observes real redirect, session and LiveView/HTTP status. A unique admitted machine request can prove a forbidden domain effect without claiming physical guest success; if a guest is selected, a separately observed guest nonce can strengthen the positive journey. An HTTP 302 or flash alone is not proof of zero authority or zero effect. A lost SMTP ACK or POST response is **unknown** until the ledger and database are reconciled; duplicate SMTP acceptance is permitted under uncertainty.

**Source and intended contract.** `marshall/lib/marshall_web/automatic_magic_sign_in_live.ex:7-33` renders a CSRF-protected remembered POST without GET-side token action. `marshall/lib/marshall_web/router.ex:150-185` installs authentication and magic-link routes. `marshall/lib/marshall/accounts/auth_emails.ex:9-75` binds token to recipient and commits a per-recipient outbox/cooldown; `deliver_auth_email.ex:12-77,89-107,113-160` rechecks stored token, sends through SMTP and records terminal status. `marshall/lib/marshall/accounts/user.ex:144-199` wires sign-in and request actions. `magic_link_sign_in.ex:6-56` fences authoritative login issuance and revokes the strategy's post-commit token. `marshall/lib/marshall_web/controllers/auth_controller.ex:18-66` verifies that stored login. `marshall/lib/marshall/accounts/security.ex:42-60,223-263` binds completion to a verification row and credential generation. `marshall/lib/marshall_web/live_user_auth.ex:23-103` checks the stored login before protected LiveView work; `security.ex` `recent?/1` gates passkey rename/remove on a same-login verification within fifteen minutes and `live_admin_auth.ex` redirects an administrator mutation without a passkey to `/settings/security?return_to=...`. ADR-0131 states the GET/POST separation; ADR-0160 (superseding ADR-0123) places passkey verification at the privileged mutation boundary, not the read boundary; `marshall/test/marshall_web/magic_link_flow_test.exs:75-137` and `mfa_login_history_test.exs:17-70` are existing scoped tests.
