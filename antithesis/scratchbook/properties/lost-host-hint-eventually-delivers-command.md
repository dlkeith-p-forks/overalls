# lost-host-hint-eventually-delivers-command

P1; high confidence; liveness. Proposed `Sometimes(condition)` message **"Committed host command reached Lilly after notifier isolation healed"**, where `condition` means a specific committed operation was subsequently accepted by Lilly's authenticated exchange and its physical result was observed. This is a semantic progress state, not `Sometimes(true)` or a deadline assertion. SDK instrumentation is **missing** per [fresh scan](../existing-assertions.md).

Source: `marshall/lib/marshall/control/hints.ex:3-16,60-106` sends hints through PostgreSQL in the mutating transaction but declares them non-authoritative; `:125-148` broadcasts only closed validated hints and exposes local resync. `marshall/lib/marshall/control/hints/relay.ex:3-8,20-54` watches Oban notifier status and resyncs subscribers on recovery. `marshall/lib/marshall/control/socket.ex:70-74` pushes hints/resync. `lilly/lib/lilly/control/link.ex:31-45` uses host-command hints only to request an exchange; `lilly/lib/lilly/control/runtime.ex:400-429` retains periodic one-second exchange and a single in-flight call. ADR-0141 documents shared PostgreSQL and notification loss/backstops. Existing `marshall/test/marshall/control/hints_distributed_test.exs` and `hints_test.exs` are targeted test presence, not a hosted run.

History: start two independent Marshall releases on one primary and Lilly with a current credential/session. Cut one Marshall notifier connection, commit a uniquely identified host operation on the other node while its hint is lost, then heal notifier and Control transport. Permit fair scheduling and available database/host resources. Let Lilly's periodic exchange and relay recovery compete; duplicate a stale hint afterward. Observe a real command acceptance and final physical receipt rather than only `:control_resync` delivery.

Independent oracle: workload records the exact committed operation ID before the cut, then checks authenticated Lilly acknowledgment, immutable physical outcome and native guest state for that ID. A valid stale or duplicate hint must never authorize a different command (cross-check current DB intent). Record whether progress came through the periodic backstop or resync; the property accepts either. Permanent partition, invalid credential, unsupported protocol, physical refusal and deliberately unavailable guest are outside its fairness preconditions.

SUT guidance: `Reachable` **"Marshall notifier recovered after losing a host command hint"** at `Relay.handle_info/2` helps reach the case; `Reachable` **"Lilly periodic exchange recovered command after lost hint"** records the distinct backstop path. The progress assertion belongs to a workload with operation/physical witnesses.

Values: 0/1/many lost hints; notifier isolated/solitary/clustered; old/new Control socket; duplicate/forged/stale valid-form hint; 1-second runtime tick, 1/2/max in-flight requests, reconnect jitter through the configured 4-second ceiling. This is application/notifier recovery over a stable PostgreSQL primary, not PostgreSQL leader failover or quorum. Real host/native execution is needed for the effect clause; service-only mode can assert durable command delivery.
