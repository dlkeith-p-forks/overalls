# host-enrollment-receipt-follows-live-health

**Type and priority.** Safety, P1, high confidence in the accepted conditional contract. Primary `Always` SDK message: **"Host enrollment receipt follows authenticated binding and live role health"**. A new enrollment receipt and resumed automatic polling may appear only for the exact pinned host identity/revision/storage binding after the serialized enrollment, candidate activation and live role verification. After the in-progress marker is published, failed or interrupted enrollment keeps polling gated until an exact retry completes. `Always` checks every receipt/polling transition. A supplementary `Reachable` message **"Host enrollment retry completed exact prepared operation"** guides the real retry path. SDK instrumentation is missing per [fresh scan](../existing-assertions.md).

**Source and decision.** ADR-0045 requires pinned administrative SSH, an immutable operation UUID, retry of the same current credential, disabled new registration until deployment and a fresh execution-ready report. `marshall/lib/marshall/compute/enrollment_preparation.ex:19-85` binds operation ID, action, request and credential in one transaction and rejects inactive/conflicting retries. `nix/packages/host/preparation.py:330-345,348-395` authenticates/locks and persists the private retry identity before issuance; `:464-517` validates the returned operation, seals changes and recovers partial publication. `nix/packages/host/enrollment.py:550-588` locks against automatic update, verifies current binding and gates polling with a private marker; `:624-650` migrates/activates, verifies, then publishes storage/enrollment receipts and ungates polling. Existing fleet updater properties concern an already enrolled host's healthy closure, not this authority transition.

**Workload and independent oracle.** Use the real operator helper, pinned SSH, Marshall transaction and installed NixOS host with native storage identity. Retry the same preparation UUID after lost SSH reply or interrupted ciphertext/public file publication; attempt conflicting request and retired/inactive credential; run explicit enrollment with faults at marker, stage, activation, role verification and receipt writes. Compare Marshall `EnrollmentOperation`/current credential IDs through a restricted read-only database oracle, private retry journal's public metadata, installed host SSH key and ZFS GUIDs, systemd polling mask/timer state, Lilly current Control report and physical guest/host identity. Never expose credential material, private journal ciphertext, SSH arguments or tokens in diagnostic logs or assertion metadata. A receipt cannot be inferred from a successful CLI exit alone.

**Value families and guidance.** First preparation/same UUID retry/conflicting UUID payload; valid/wrong pinned SSH key; valid/stale storage GUID; active/expired/retired credential; before/after operation commit and lost reply; before/after each ciphertext publication; stage/preflight/migrate/activate/health/receipt interruption; zero/two valid health polls; automatic timer masked/unmasked. Use SUT markers on transaction commit, marker publication, health proof and receipt publication. Existing `nix/tests/machines/host-enrollment/` and `enrollment-operator/` show source fixtures, but source presence is not current execution. Full host trust and ZFS identity require native NixOS; a hosted mock of SSH or storage cannot prove this boundary.

**Open question.** Can a native source-built fixture independently capture exact Marshall operation identity, Lilly polling status and physical storage GUID during the same interrupted enrollment? The existing fixtures cover parts of the path, but their combined fault schedule and current passing result are not established here. This is a test topology question, not a confirmed SUT defect.
