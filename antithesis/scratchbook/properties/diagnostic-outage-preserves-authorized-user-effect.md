# diagnostic-outage-preserves-authorized-user-effect

**Type and priority.** Conditional liveness, P1, high confidence in the accepted separation, medium confidence in hosted composition feasibility. Primary `Sometimes(condition)` SDK message: **"Authorized guest effect completes during a finite diagnostic outage"**. The condition is `valid_authority && diagnostic_fault_active_at_effect && independently_witnessed_guest_effect_and_matching_physical_receipt && fault_subsequently_released`; it is evaluated after the finite fault has ended from a retained, ordered history. It is a nontrivial semantic success under a required fault, so `Sometimes(condition)` is appropriate; `Reachable` at an outage branch alone would not prove user progress. Business dependencies must remain available. No unconditional deadline or universal completion from a permanently blocked service is asserted. The [fresh scan](../existing-assertions.md) found no SDK callsite.

**Source and distinction.** ADR-0149 explicitly requires Control and VM lifetime to progress with diagnostic stores down and states diagnostics confer no authority. `lilly/lib/lilly/control/runtime.ex:1188-1191` keeps physical outcome acknowledgement independent of diagnostic delivery; `lilly/lib/lilly/vm/journal.ex:145-157` preserves matching authoritative outcome acknowledgement. `elixir/request_accounting/lib/overalls/request_accounting/producer.ex:49-67` returns `:unrecorded` on unavailable measurement; `producer/server.ex:42-68` records the gap instead of inventing a ticket. `lyra/src/telemetry.rs:225-238` sends guest tool telemetry through bounded observer work after terminal transition. Recorder capacity/restart and trace spool quota/archive rows check telemetry custody and measurement quality; none requires the user-visible effect while those systems fail. The separate current native Lilly-to-Tempo fixture is historical recorded evidence at its captured revision in ADR-0149, not a current Antithesis baseline.

**Workload and independent oracle.** Admit a valid VM start/provision or a lease-valid guest command, then stop the authenticated request recorder, diagnostic spool and Collector independently and in combinations, including ACK loss and full queue; leave PostgreSQL, Control authority, Lilly native owner and guest transport intact. Keep the diagnostic fault active through the independently witnessed effect, then release it so the outage is finite. Use a guest-written nonce/file read through a separate authorized path and matching native VMM/boot identity plus Lilly journal/Marshall operation receipt as the success witness. Record measurement as unknown/gapped when appropriate; do not equate missing trace or log with failed work, and do not use a trace as the effect oracle. Keep tokens, command arguments, guest bytes and payloads out of SDK messages and all diagnostics; local oracle retains only opaque effect IDs and comparison results.

**Value families and guidance.** Recorder/producer/diagnostic spool/Collector each alive, killed, stalled or full; fault before/after admission and outcome commit; accepted/lost diagnostic ACK; one/more than 64 valid native transitions; start versus guest command; current/stale user authority; finite outage and explicit release. A stale or revoked request should be refused, not counted as a liveness failure. Place SUT branch markers on `:unrecorded` admission, journal outcome persistence, Control outcome ACK and observed guest effect. Hosted real services may prove user progress with real BEAM, local recorder and guest TCG, but require native machine evidence for Firecracker/physical guest isolation. A pure model, unit test or aggregate suite exit cannot establish the physical effect.

**Open question.** Which hosted or native fixture can fault recorder, spool and Collector separately while preserving the real authenticated producer, Lilly Control exchange and a booted guest independent effect oracle? The topology design and existing native fixtures suggest seams, but no replacement harness or current native execution has been demonstrated. This is a verification gap, not a confirmed production defect.

## Evaluation and proof boundary

**Proof boundary:** Draft selection: `integrated-zfs-guest`. proposed-integrated-ZFS-backed-Lilly-with-TCG-guest; unbuilt; independent witness: current authority and boot tuple plus independent guest editor/SSH/file/PTY effect. Native companion: required. Current state: unexercised; no hosted catalog-property evaluation or baseline exists.

**Evaluation follow-up:** `Sometimes` is existential; any selected per-operation progress claim needs a separate measured post-heal terminal check. Record exact selected image/profile, guest family, source provider/revision, drive count and enabled capability as applicable; unselected variants are unexercised.
