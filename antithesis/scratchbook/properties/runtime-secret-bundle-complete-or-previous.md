# runtime-secret-bundle-complete-or-previous

**Type and priority.** Safety, P1, high confidence in the publication contract. Primary `Always` SDK message: **"Runtime secret bundle publication is complete or retains the previous bundle"**. At each publication checkpoint the destination namespace points to the prior or new validated complete directory with selected files and required ownership/modes; malformed, missing, undecryptable or symlinked input must leave the prior destination unchanged. This is a must-hold namespace/custody invariant, hence `Always`. A consumer that separately opens paths across an exchange may see two generations, and a held descriptor to the retired directory may lose entries during cleanup; this property does not promise a multi-open transactional read. Supplementary `Reachable` message **"Runtime secret bundle rejected missing value while old bundle stayed readable"** selects a meaningful refusal branch. The [fresh scan](../existing-assertions.md) found no SDK assertion.

**Source and decision.** `nix/modules/secrets/CONTRACTS` explicitly requires full validation, atomic directory publication and private identities. `nix/modules/secrets/prepare.py:110-145` bounds and discards resolver output; `:148-179` validates selected values and size; `:182-190` uses `renameat2(RENAME_EXCHANGE)` for existing directories; `:219-257` builds files in a private staging directory, fsyncs files and optionally the directory/namespace, then exchanges/replaces the directory. `:297-356` creates and removes the derived private identity. ADR-0041/0044 keeps recipient policy and recovery-only ciphertext separate from machine-readable runtime bundles. The existing updater health property inspects candidate secret freshness, but does not check the atomic read boundary or temporary identity custody. The existing recorder/trace quota rows are unrelated.

**Workload and independent oracle.** Start a real NixOS consumer bound through its declared `LoadCredential`/secret unit and a read-only observer. Rotate synthetic sealed values under actual SOPS/age and host identity; inject missing/malformed value, wrong recipient, untrusted/symlink path, resolver timeout and interruption around exchange. Pause the publisher at pre-exchange and post-exchange checkpoints, then compare the destination's complete generation, modes and ownership with the two known synthetic generations and test real consumer readiness after settled publication. On validation rejection, the old complete generation remains readable. Check the transient derived identity is absent after both success and caught failure, while a process-crash outcome is judged only after cleanup/retry has run. Never print or store secret values, private keys or ciphertext in logs, test failure messages or SDK metadata; the oracle may compare keyed generation markers locally without exposing them.

**Value families and guidance.** One/two/many selected files; existing/absent destination; root/service group; raw/environment formats; valid/missing/empty/oversize/decryption-failed value; canonical/symlink path; before/during/after stage fsync, exchange and parent fsync; cleanup success/failure; old/new generation. Place `Reachable` at actual validation refusal and exchange boundary. A Python property test of generated files checks logic; NixOS native integration with real permissions, systemd credentials, SOPS and filesystem namespace checks is preferred. A process SIGKILL between durable steps may leave staging until cleanup, so the invariant concerns the published destination, not absence of every temporary file at every instant. Source and fixture presence are not an executed native proof.

**Open question.** Can the native secret-custody fixture schedule a crash immediately before and after `RENAME_EXCHANGE` while the independent consumer samples the published directory? `nix/tests/machines/secret-custody/driver.py` covers generated seal/recover/rotate/missing/restore histories, but this exact interruption and current execution status need confirmation. This is an implementability limit, not a defect claim.
