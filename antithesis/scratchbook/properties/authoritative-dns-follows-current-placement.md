# authoritative-dns-follows-current-placement

**Type / priority:** Safety, P0. **Primary SDK assertion:** `Always` **"Authoritative DNS addresses follow the current published placement"** for each observed, non-expired A answer after a current publication has converged. Use a separately named `Sometimes` condition to witness a destination A answer and successful destination request after relocation; otherwise repeated SERVFAIL could satisfy the safety check vacuously.

**Property:** The actual authoritative answer for a canonical VM hostname, including its editor alias when selected, must name only addresses from the current valid route. Once the destination route has been published and each selected Audi replica has refreshed, the answer and the resulting HTTPS/SSH connection reach the destination; old source addresses cannot persist as a successful authoritative A response. During invalid or expired publication, SERVFAIL is an unavailable state, not a stale successful answer or proof of convergence.

**Source trail:** `marshall/lib/marshall/ingress/routes.ex:106-184` revalidates execution, certificate installation and gateway generation before returning addresses; `marshall/lib/marshall/ingress/publications.ex:113-223` builds route and editor publications from one DB statement, completed start and committed relocation readiness. `audi/lib/audi/dns/replica.ex:1-103` refreshes a complete replica; `audi/lib/audi/dns/directory.ex:26-121` rejects regressed revisions and expires per-route entries; `audi/lib/audi/dns/authority.ex:103-121,158-220` emits authoritative NOERROR, NXDOMAIN or SERVFAIL and maps editor aliases to a neutral publication. `antithesis/scratchbook/deployment-topology.md:82-96,175-190` names separate Audi and guest/host execution boundaries. The current catalog has no actual DNS-answer property.

**Real actions and oracle:** Start a VM through the public lifecycle route and record the old current host/placement/session plus both authoritative Audi IPs and the exact A RRset/TTL from raw UDP and TCP queries with recursion disabled. Initiate a public relocation; independently observe committed destination placement, current destination gateway address, route revision and physical new guest boot. After a successful current publication revision is observed on each Audi replica, query each real UDP/TCP listener repeatedly and compare decoded owner name, AA flag, response code, RRset and TTL with the route's destination addresses. Connect to each returned address with the canonical SNI or SSH hostname and a unique destination boot/file nonce. Probe the old source address separately for refusal. Avoid treating a resolver cache, Marshall JSON, a DNS request counter, or a bare successful TCP handshake as an authoritative answer or destination proof.

**Fault/interesting values:** Drop publication hints, restart one Audi DNS directory/replica, lose a refresh response, expire one route while the complete snapshot remains fresh, relocate while an earlier response is in flight. A pre-cutover cached answer within its emitted TTL is a separate client-cache condition; assertion comparisons must use fresh direct authoritative queries after each replica's accepted revision, not retroactively call legitimate earlier replies wrong. Select multi-address gateways and the editor alias as variations, preserving the exact queried owner name.

**Environment proof:** Hosted `access` can test actual Audi DNS publication and listener bytes against Marshall's route, but cannot prove destination guest usefulness without `guest-journey` TCG or native KVM. TCG needs exact QEMU/backend/overlay boot receipts and host peer CID 2 for its guest services; it cannot establish Firecracker isolation or independent hardware. Full successful relocation needs two Lilly execution boundaries or native fleet. DNS responses themselves must be actual network packets in every case.

**Questions / investigation log:** The exact event that marks an Audi replica's accepted post-relocation revision must be exposed to the workload without replacing the public DNS check; source inspected: publication SQL, replica, directory, authority and topology. No current hosted or native run demonstrates convergence. If a replica remains unavailable, record that state and test conditional progress only after finite recovery; do not label timeout or SERVFAIL an expected refusal.

## Evaluation and proof boundary

**Proof boundary:** Full DNS-plus-connection claim is a native two-Lilly KVM/ZFS acceptance target: observe each Audi authoritative DNS packet, the current destination physical boot and a real destination SSH/HTTPS nonce, with old-source refusal. The hosted `access` template can check only DNS packets against current Marshall publication; it cannot prove destination guest usefulness or a completed relocation. No full-property hosted template is selected. Current state: unexercised; no hosted catalog-property baseline exists.

**Evaluation follow-up:** Record exact selected image/profile, guest family, source provider/revision, drive count and enabled capability as applicable; unselected variants are unexercised.
