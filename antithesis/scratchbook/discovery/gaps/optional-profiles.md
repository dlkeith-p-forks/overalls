# G6: optional profiles and mandatory configuration variation

The one new independent P0 candidate is [inception-parent-publication-cannot-confer-child-authority](optional-profiles/inception-parent-publication-cannot-confer-child-authority.md). A parent Inception namespace/publication/stream lease permits transport to a child listener, but cannot authenticate a child user or forward new bytes after parent authority expires or changes. The existing private-web, readiness and source properties do not cross this recursive control-plane boundary. Its proposed primary SDK assertion is `Always` **"Inception nested forwarding requires a current parent lease and child effects require child authorization"**. A dedicated positive `Sometimes` must witness authorized inner HTTPS or SSH bytes across both layers. This is proposed instrumentation, not a test result; the [fresh assertion scan](../../existing-assertions.md) found no Antithesis SDK calls.

The other axes below primarily require a **mandatory variation roster** on existing or separately proposed invariants. A single OSS/NixOS/default GitHub/one-drive result cannot discharge them. The portfolio's `source-v2-*`, `guest-workspace-*`, `guest-readiness-*`, `guest-identity-*`, `backup-*`, clone/relocation and isolation/egress properties remain their canonical invariants. Multi-drive *all-drive lineage* is an independent physical target already called for by [coverage finding 3](../../evaluation/coverage-balance.md); it should be synthesized with that gap's clone/resize/relocation work, rather than duplicated under a profile label. The roster does not assert that every Cartesian combination is useful: each row names the actual branch and its witness.

The Inception image rebuild is an **offline, locked closure** prerequisite, never a runtime network-download step. `nix/packages/guest/inception/image-builder.nix:43-81` retains recipe, seed derivation closure and pinned source references; `nix/tests/machines/inception/probe.exs:447-453` checks their presence. A campaign must verify a new independent public root can rebuild from that local cache and then boot the enrolled image, while keeping instance credentials out of Nix inputs. Successful Nix evaluation or a seed image alone does not prove the nested runtime rebuild or physical boot.

One documentation discrepancy affects roster design: `marshall/priv/docs/commands.md:60` says Inception cloning is unavailable, while `Marshall.Compute.Cloning.execute(:submit, ...)` (`marshall/lib/marshall/compute/cloning.ex:57-89`) has no profile exclusion and the native `zfs-guest` fixture explicitly clones both Inception drives (`nix/tests/machines/zfs-guest/driver.py:250-271`). This is not evidence of a current failing clone. Synthesis should retain the actual two-drive clone variant and route the stale command statement for documentation reconciliation, rather than silently excluding the path.
