# G4 — guest agent and named integration effects

Repository-only targeted discovery. Current Antithesis instrumentation for these guarantees is missing according to [the existing assertion scan](../../existing-assertions.md). This report proposes tests, not a reproduced defect or a passing hosted run. The three independent candidates below cover the missing effects and outcome boundary. Existing `galileo-accounting-delay-does-not-renew-old-grant` addresses the initial grant's age during recorder admission; `lease-expiry-independent-of-blocked-renewal` spans generic satellite effects; terminal input properties concern a different process and stream. None ties a durable agent command to actual guest effects, exercises a supported long fetch through its terminal transition, or compares a named integration's destination and injected credentials to an independent origin log.

These are deliberately not one property. A completed model turn can conceal duplicate guest effects; a terminal or command row does not measure the guest filesystem. A failed guest tool transition can coexist with one successful remote GET. An integration response can be a 502 after the local origin accepted a request. The oracle must count the effect at its owner and reconcile it with authority and identity, while treating an ambiguous response as unknown until the independent witness is read.

Topology: the first two select `control-core` plus Ziggy/Audi, one real Lyra guest under `guest-vmm` or the existing native agent fixture, and a deterministic local provider that issues one fixed tool command. The second additionally selects a separately faultable local TLS origin reachable through guest networking. The third selects the `upstream/integration` services plus Audi, Lilly pre-NAT binding and a genuine source guest for the complete identity claim; a host-bound controlled request without guest can prove the narrower Galileo authorization and routing logic only. The integration fixture owns two HTTPS origins to detect wrong-origin routing. These additions are scoped selections of the [deployment menu](../../deployment-topology.md), not a claim that the current harness exists. TCG proves real guest user-space effects, not Firecracker isolation, physical host separation or production public-provider behavior. The native executor-loss fixture at `nix/verification/tests/machines/executor-loss/driver.py:460-513` and its captured review at `docs/architecture/reviews/2026-09-26-executor-loss-histories.md:120-143` are prior scoped evidence for one started-loss/retry sequence, not a current Antithesis run or proof across the new fault menu.

The Lyra tool path is a distinct domain from Marshall-owned `web_search` (`marshall/lib/marshall/agents/web_search.ex:69-85,192-195`; ADR-0107). Its credential and effect must not be conflated with a guest `web_fetch` or Galileo integration credential. Hegel may be useful for local generated properties, but [the Hegel feasibility report](../../hegel-sdk-feasibility.md) shows the Python adapter presently omits the required test location and defaults explicitly to deterministic `ci`. Its documented native ABI is `hegel_settings_set_test_location(ctx, settings, file, begin_line, class_name, function) -> hegel_result_t` at `nix/verification/hegel/hegel.h:925`. These candidates specify SDK semantics; no Hegel property output or Antithesis coverage is claimed.
