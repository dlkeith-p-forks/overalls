# editor-save-survives-worker-recovery

**Type / priority:** Safety, P0. **Primary SDK assertion:** `Always` **"Personal editor save survives worker recovery under its owner's UID"** on every acknowledged save and later recovered read. A separately named `Sometimes` message for a saved marker read after recovery is needed for meaningful progress under finite recovery; an editor origin or 200 asset response is no save witness.

**Property:** A writer with current editor authority can open the real browser workbench, save bytes to its own guest workspace, and recover those same bytes and numeric UID after broker or worker loss and a fresh authorized open. A broker restart must not change worker/account custody; a worker loss may create a new worker but must preserve the personal files. A stop/start variant must correlate the new physical boot before claiming the reopened editor.

**Source trail:** `marshall/lib/marshall/editor/authority.ex:35-48,163-224,244-260` binds launch/open/renew to current write authority, permanent GuestAccount and UID, image, execution and host session. `audi/lib/audi/http/editor.ex:9-55` admits exact Origin and relays editor HTTP/WebSocket through current authority. `nix/packages/vscode-web-broker/CONTRACTS:1-25` requires fixed guest gateway, peer UID, independent worker lifetime and refusal on mismatched socket custody. `nix/packages/vscode-web-broker/src/lib.rs:232-340` validates the boot-bound preface and UID range. `nix/modules/otel-guest/browser_journey.py:536-640` exercises browser edit/save/readback and terminal UID, and `nix/tests/machines/vscode-web/fleet.py:344-405` defines broker, worker and stop/start cases. These are fixture designs, not a current passing run.

**Real actions and oracle:** Provision an editor-capable current image through Marshall, with the approved release/asset receipt and a current writer. Before *any* browser write or fault, read and hash the target guest file's exact bytes and stat its UID/home; this prevents a preexisting fixture marker from masquerading as a save. Open via Marshall's `/machines/{id}/code`, complete the Audi editor login, use the browser editor to replace or append a fresh run nonce and invoke actual save. Independently read the exact guest file bytes, fsync/flush if durability across guest restart is claimed, and verify owner UID equals Marshall's GuestAccount UID and worker `/proc`/socket peer UID. Interrupt broker and worker in separate histories; reopen through a fresh authorized browser path, read the saved marker in editor and guest file, verify home/UID and no foreign account file change. For stop/start, record old and new kernel boot UUID with exact host/placement/epoch/generation/session; assert the old stream cannot deliver a post-start nonce.

**Fault/interesting values:** Broker death between preface and worker reuse, worker death after save acknowledgment, Audi restart or renewal loss during an open editor, same-placement new guest boot, and a second writer with a distinct origin. A denied login or setup timeout must be recorded as unexercised, not a successful saved-byte invariant. Compare pre-fault bytes before the browser writes, then post-save bytes before and after fault; never infer save from a workbench title or HTTP 200.

**Environment proof:** A hosted Audi/Marshall refusal path cannot prove file effects. `guest-journey` TCG needs real guest TCP 4444 broker, QEMU/backend and overlay receipts, exact boot tuple and the host peer CID 2 seen by guest vsock services. It can prove guest file/UID behavior under emulated process faults, not Firecracker isolation or native ZFS durability. Native KVM acceptance is separately required for physical guest custody claims.

**Questions / investigation log:** The browser fixture's save acknowledgment and independent file read must be adapted to the selected TCG image without replacing the real workbench with a test writer. Source examined: Marshall Editor authority, Audi relay, broker contract/validator, browser journey and fleet source. No current hosted image or run demonstrates the editor path; any suspected worker reuse bug remains a hypothesis until a real save/fault/reopen transcript discriminates it.
