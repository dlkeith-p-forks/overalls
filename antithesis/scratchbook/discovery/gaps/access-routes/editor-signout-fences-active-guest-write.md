# editor-signout-fences-active-guest-write

**Type / priority:** Safety, P0. **Primary SDK assertion:** `Always` **"Signed-out editor session cannot write new guest bytes"** for each post-commit old-session write attempt. Add a separately named `Sometimes` witness for an authorized pre-sign-out save and fresh post-sign-in save, so a permanently unusable editor does not pass vacuously.

**Property:** Ordinary browser sign-out revokes the stored login that backs an editor cookie and lease. An established editor WebSocket and old cookie cannot write new guest bytes after revocation takes effect; a new login and current write authority are required. This tests the editor's personal transport and file effect, distinct from generic private-web lease expiry.

**Source trail:** `marshall/lib/marshall/editor/authority.ex:163-224,306-329` rechecks stored login, account, current write authority, execution and host session on open/renew. `audi/lib/audi/http/editor.ex:9-55` relays the editor under renewable authority and checks canonical Origin. `audi/lib/audi/http/editor_browser.ex:13-100` stores the host-only cookie. `nix/tests/machines/vscode-web/authorization.py:13-100` defines a real sign-out/WebSocket closure and HTTP reauthentication fixture, but its source does not establish a current pass. `nix/modules/otel-guest/browser_journey.py:536-640` shows a real browser save and guest UID probe.

**Real actions and oracle:** Open an editor via Marshall `/machines/{id}/code`, establish a live Audi WebSocket and save a baseline marker; independently read exact guest file bytes and UID before fault or sign-out. Complete ordinary sign-out through Marshall's browser UI and record the committed login revocation boundary. Attempt a fresh marker write over the old WebSocket and through a new request carrying the old cookie. Observe closure or refusal, then independently read the guest file to prove the marker is absent. A redirect or closed socket alone does not prove the absence of a previously buffered write; correlate the write's send time with the sign-out commit and inspect file bytes after the old lease's maximum valid deadline. A new browser sign-in and new editor cookie must save a distinct marker as positive control. Keep frames, cookies, paths and file contents in a private fixture ledger.

**Fault/interesting values:** Drop authority hints, stall renewal during sign-out, restart Audi, crash broker/worker while an old WebSocket is closing, and race a new request at the lease deadline. Bytes accepted before the logout commit are outside this invariant. A timeout or unavailable guest is not observed refusal. An unchanged file due to a failed setup save is not sufficient; require the positive baseline and fresh sign-in write.

**Environment proof:** Hosted Marshall/Audi can prove cookie refusal and stream closure, but the no-new-guest-byte assertion needs editor-capable `guest-journey` TCG or a current native KVM guest. Observe actual guest TCP 4444 broker, UID and exact VM/host/placement/epoch/generation/session/kernel boot UUID. TCG needs QEMU/backend/overlay receipts and host vsock peer CID 2; it cannot establish Firecracker isolation or native physical custody.

**Questions / investigation log:** The precise old-stream closing deadline must be taken from the real renewable lease implementation and observed after finite recovery; do not invent instantaneous byte revocation across an already accepted frame. Source examined: Editor authority, Audi relay/browser, authorization fixture, browser journey and topology. No composed current run or confirmed lingering-write defect found; report it as a hypothesis until the committed sign-out and guest-file effect discriminate it.
