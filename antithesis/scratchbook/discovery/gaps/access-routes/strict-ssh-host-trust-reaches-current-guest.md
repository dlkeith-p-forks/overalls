# strict-ssh-host-trust-reaches-current-guest

**Type / priority:** Safety, P0. **Primary SDK assertion:** `Always` **"Strict SSH host certificates reach only the current guest execution"**; a bad accepted SSH transcript violates safety whenever checked. Add a separately named `Sometimes` witness for a completed, strict, post-move guest shell, so refusal-only runs cannot pass the selected journey vacuously.

**Property:** With client CA trust installed through the public installer, a new SSH connection for the canonical VM hostname accepts only valid gateway and guest host certificates for the expected principals and reaches the current VM execution. An obsolete source route, wrong principal/CA/certificate, or raw unsigned fallback never yields guest command bytes. The user still needs a registered signing key and current write authority; a host certificate is no user grant.

**Source trail:** ADR-0124 `docs/architecture/decisions/0124-unified-ssh-host-ca.md:30-77,91-102` defines the CA, per-boot guest key, principal and strict client trust. `marshall/lib/marshall/ssh/host_certificates.ex:26-31,102-128` derives principals under gateway/VM authority; `marshall/lib/marshall/ssh/guest_access.ex:220-321` distinguishes boot certificate eligibility from completed, current key/login execution. `marshall/lib/marshall/ingress/routes.ex:106-184` projects the current gateway addresses and host key. `audi/lib/audi/ssh/listener.ex:55-75` selects certificate-first host keys. `nix/tests/machines/fleet/scenarios/user-ssh-journey.py:533-556,990-1078` gives a current native fixture design with CA-only known_hosts, strict OpenSSH, moved placement, retained home bytes and changed guest key; its source is no current run receipt.

**Real actions and oracle:** Provision a VM with a selected NixOS or Ubuntu SSH-capable image; register two synthetic user keys, install the public CLI/CA trust, and use the generated OpenSSH `ProxyCommand` with `StrictHostKeyChecking=yes`, `BatchMode=yes`, no prompt or unsigned fallback. Before relocation, write a unique file in the guest and record its bytes, UID and kernel boot UUID through SSH. Move through Porsche's public `relocate` action, wait for completed relocation/readiness, then connect using the same client trust and hostname. Parse the actual OpenSSH certificate/principal/CA proof and read a fresh remote nonce, current boot UUID, UID and retained file; compare with the committed current host/placement/epoch/generation/session and independent destination QEMU/guest or native VMM observation. Probe the old source route with an explicitly pinned source address and a wrong-principal/CA certificate; neither may return the nonce. A timeout is unavailable, not proof of refusal. Do not log private keys, raw terminal output or secrets.

**Fault/interesting values:** Lose the source Audi route update, restart the destination Audi or Marshall during issuance, rotate the Audi gateway key, interrupt SSH just after signature verification, and retry with old/new guest certificates. A normal current SSH shell is required as a positive control after finite recovery. Distinguish a certificate accepted by a client from its subsequent current-key/Cedar decision. The stable CA cannot itself prove correct placement.

**Environment proof:** Hosted `access` without a guest can only establish gateway refusal. `guest-journey` TCG can validate a real guest certificate and actual guest bytes through QEMU, with host vsock peer CID 2 and exact boot tuple; it cannot claim Firecracker isolation or independent physical hosts. Full two-host relocation acceptance needs two separate Lilly boundaries with real guest effects, preferably a current native KVM fleet run.

**Questions / investigation log:** The current topology has no built hosted fixture, so the exact OpenSSH certificate transcript capture and source-address pinning adapter must be specified and reviewed. Source examined: ADR-0124, host issuer, guest-access, route projection, Audi listener, native SSH journey, TCG feasibility. No current run/repro or tenant fault capability found. If no actual guest and strict client transcript is obtainable, keep this candidate unexercised rather than count a route API or public certificate response as success.
