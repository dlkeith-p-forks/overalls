## PostgreSQL is a real authority dependency

Marshall uses AshPostgres, Ecto, Postgrex and Oban (`marshall/mix.exs:63–86`). `Marshall.Operations.RuntimeConfig.from_env/1` requires a writable primary, one pool per replica and a connection budget covering pools, notifiers and ten operator connections. It installs `synchronous_commit=on`, a fifteen-second idle transaction deadline, one-second active client checks and TCP loss detection (`marshall/lib/marshall/operations/runtime_config.ex:118–170`). `Marshall.Compute.Ledger` performs row locking and obtains transaction time from `SELECT clock_timestamp()` (`marshall/lib/marshall/compute/ledger.ex:141,233`). These are external behaviors, not properties established by an in-memory resource model.

The declared Overalls deployment is PostgreSQL 18 on IPv4 loopback with TLS, SCRAM, `max_connections=64`, fsync and full-page writes (`fleet/hosts/overalls/configuration.nix:123–146`). Dungarees explicitly excludes PostgreSQL (`fleet/hosts/dungarees/configuration.nix:31`). This inventory does not declare a replicated production database; synchronous commit must not be described as synchronous standby replication. Architecture discussions and HA fixtures are separate deployment scenarios.

Use real PostgreSQL and actual migrations for transaction, uniqueness, idempotency, Oban scheduling, locking, uncertain commit and connection-reclamation properties. Fault the application-to-database connection and database process/storage separately. An independent observer can query committed rows through a separate connection and compare them with the workload's durable operation history. Database state alone cannot establish physical guest execution; conversely a physical receipt cannot establish a committed admission. A database stand-in would remove the central race boundary.

The shared transport is an integration dependency of the apps even though it belongs to the repository. ADR-0142 and `protocol/lib/overalls_protocol/control/client.ex` define verified TLS IPv4, negotiated limits, heartbeats and reconnection; a dropped in-flight request is unproven and must not be automatically replayed. Network partitions, DNS changes and malformed responses should reach the exact transport, not a synthetic success callback.

## Mail, authentication, DNS and certificates

Marshall's account strategy is magic-link plus remembered credentials backed by stored tokens (`marshall/lib/marshall/accounts/user.ex:21–39`); passkey ceremonies and time-limited elevation are implemented separately (`marshall/lib/marshall/accounts/security.ex`). A scoped case-insensitive search found no direct OIDC/OpenID/OAuth implementation in the eight applications, Lyra or Nix modules/packages. Do not invent an OIDC server dependency. Underclass is separately fetched source; its provider authentication internals cannot be inferred from that negative search.

Mail supports verified authenticated remote SMTP or explicitly selected literal-loopback relay (`marshall/lib/marshall/mailer/config.ex:17–101`). The Nix relay accepts generic, SES or Resend endpoints and reads credentials through systemd custody (`nix/domains/system/smtp-relay/default.nix:17–25,38–54,76–89`). The real delivery action holds the outbox lock through submission, uses a ten-second total deadline and preserves a Message-ID derived from immutable delivery UUID (`marshall/lib/marshall/accounts/deliver_auth_email.ex:12–34,104–131`). SMTP acceptance and database delivery status are separate outcomes; neither establishes inbox delivery or exactly-once mail across commit ambiguity.

A deterministic SMTP server must model DATA acceptance followed by lost reply, rejection, TLS failure and stalled acknowledgement. Its independently persisted acceptance history provides the oracle for duplicate submission and stable message identity. Repository fixtures already exercise these conditions (`nix/verification/tests/machines/smtp-relay/driver.py:48–72`), but their presence is not recorded execution in this discovery. Keep token consumption and browser sign-in real for authentication claims; bypass login only narrows the tested lower boundary.

Public Audi wildcard issuance is Marshall-owned ACME DNS-01 with encrypted keys in PostgreSQL and in-memory Audi installation (ADR-0105). The client verifies configured issuer origin, nonce handling, response bounds, no redirects/retries and three-second request deadlines (`marshall/lib/marshall/ingress/acme/transport.ex:42–56,103–124`). Propagation checks contact every configured authoritative IPv4/TCP peer directly; there is no resolver fallback (`marshall/lib/marshall/ingress/acme/propagation.ex:15–40,62–91`). The separate host HTTPS ACME module supports Route53 DNS or HTTP-01 (`nix/domains/system/acme/default.nix:88`); these are different certificate paths.

Use local ACME and DNS endpoints with real signed certificates, JWS validation, nonce consumption and independently observed issued orders. Fault proof publication, one DNS replica, issuer replies and gateway installation independently. An issuer that returns success regardless of proof cannot test propagation. Generic resolver/DNS outages also affect fleet control origins (ADR-0095), Git and providers, while Brady specifically retains the originally admitted destination rather than replacing it with later DNS answers (`brady/lib/brady/upstream.ex:5–9`). Live DNS delegation, public CA issuance and sender-domain/inbox acceptance remain external acceptance scopes.

## Native guest, storage and artifact boundaries

Lilly's fixed utility inventory includes ZFS/zpool, mount/findmnt, nft/ip, systemd and custom Rust helpers (`lilly/lib/lilly/host/command.ex:5–44`). Mutations require a current native lock owner; owner custody, child reaping and effect uncertainty are implementation requirements. Real flock, `/proc`, pid/cgroup state and process death are necessary to test their kernel semantics. Replacing utility output with expected strings only tests interpretation of those strings.

Firecracker configuration requires trusted static x86_64 Firecracker and jailer binaries plus unshare (`lilly/lib/lilly/vm/config.ex:89–93`). Guest composition wires real OpenSSH, current-account reconciliation, host certificates, PAM checks, terminald and the Lyra agent to systemd boot dependencies (`nix/domains/artifacts/guest/default.nix:11–40,119–141`). Terminald uses host-only AF_VSOCK (`nix/domains/artifacts/terminald/src/vsock.rs:92`); guest flush, readiness, workspace transfer and terminal paths depend on actual guest/kernel behavior. ZFS clones, stream resume tokens, GUID ownership, namespace-aware deletion and capacity require real ZFS with matching userspace/kernel, rather than a file-backed approximation. Current relocation requirements are stopped-only under ADR-0155; historical live pre-copy scenarios cannot define current scope.

Images are local artifacts, not an implicit live image-download API. The background catalog publishes only full-digest-verified configured images, withholding staged candidates without delaying unrelated startup (`lilly/lib/lilly/host/image_catalog.ex:27–46,73–92`). Nix-built ext4 images prefer local build and bind exact manifest artifacts (`nix/domains/artifacts/guest/default.nix:146–155,199`). Package the exact baseline closure and guest artifacts; deliberately corrupt or remove an artifact to exercise refusal. Independently hash bytes and observe boot identity rather than accepting the catalog's own boolean as the oracle.

Guest repository launch contacts GitHub, GitLab, Codeberg and Bitbucket only from the guest. Source protocol parsing fixes exact origins (`protocol/lib/overalls_protocol/workspace_source.ex:75–78`); Codeberg/Bitbucket change heads add bounded provider APIs (`lyra/src/workspace_checkout.rs:248–303`). Real Git is preferable for ref/object/checkout behavior. Local origins need fixture repository objects and realistic advertised refs/API schemas, with deterministic TLS routing preserving hostname validation. Thirty-second process ownership and one-MiB listing bounds are implemented in `lyra/src/workspace_receiver.rs:294–344`. Compare actual checkout HEAD/content with precomputed fixture objects; sharing the SUT resolver as the oracle would hide resolution mistakes.

Diagnostic delivery is not an authority oracle.

## Recovery storage, time and feasibility conclusions

Backup orchestration is Python plus real ZFS snapshots, guest vsock flush, pg_dump/pg_restore and Restic over TLS S3 (`nix/domains/system/backups/default.nix:62–69,163`; `nix/domains/system/backups/restic.py:39–113`). Repository/password credentials are validated before every repository operation. MinIO-backed machine fixtures exist (`nix/verification/tests/machines/backups/driver.py:1–10`). Use real Restic and local S3-compatible storage for manifest/reference/restore properties; independently restore and compare bytes. Local Restic without S3 narrows transport/locking/failure claims. Provider versioning, object lock and multi-region loss remain external behavior, not application guarantees.

Time crosses database wall clock, application wall clock, monotonic timers, certificate expiry, DNS TTL and browser `Date.now()` (`Ledger.now/0`, `protocol/lib/overalls_protocol/control/client.ex:473`, `marshall/assets/js/terminals.js:451–467`). Relative authorization TTLs and elapsed operation durations require monotonic semantics; freshness/expiry require wall time. Do not assume all clocks advance identically. Inject observable skew/restart effects where possible and use independently recorded elapsed deadlines. Seven-day retained-history claims cannot be established by simply rewriting timestamps.

The lowest proposed useful boundary is real app releases, protocol sockets, PostgreSQL and deterministic provider endpoints, with explicitly modeled native effects. This can establish control/admission/replay/refusal properties only. Native lifetime, isolation, capacity, transfer, update and guest data properties additionally require usable KVM/vsock, systemd/cgroup-v2, namespaces, ZFS and exact guest closures. ADR-0033 explicitly says containers do not exercise QEMU/UEFI/ZFS/nested-KVM boundaries and requires usable nested KVM; repository-only research cannot establish Antithesis support for those capabilities. This is the principal full-system feasibility blocker.

## Assumptions

Stand-ins are separate faultable services with independent durable effect ledgers and real transport/crypto; no stand-in manufactures native success. Fixture endpoint routing must preserve closed production-origin policies rather than silently weakening TLS or credential validation. Source/test presence is not a passing-run claim.
