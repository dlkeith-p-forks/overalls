# Focus 02: State management and persistence

## Examined scope and evidence limits

This fresh pass examined Marshall's database/repository/runtime configuration, compute ledger, provisioner exchange, physical outcomes, Oban dispatch and inference totals; Lilly's intent store, actor/lifecycle journals, private-file publication, runtime receipt handling, owner cache and transfer journals; Audi's DNS directory and TLS store; Brady's cache policy, object store and recovery; Ziggy's accounting spool, checkpoints and reporter; Enrico's mirror manager, Git publication and native writer; Galileo/Porsche control clients; shared protocol Views, diagnostics and request accounting; Rust request/trace stores; terminald, browser-editor workers, Lyra guest account/workspace state; and fleet/Nix persistence, logging and backup bindings. Root and component CONTRACTS were read along with relevant local contract comments. Architecture documentation, particularly ADR-0149, was a lead to source rather than proof. Existing Antithesis artifacts were excluded from searches and were not inputs.

No application source was edited and no runtime tests were executed. Test files cited below establish available oracle/fixture mechanisms, not passing execution at this revision. This discovery has no implementation architecture impact; the intended architecture remains unchanged. It is a breadth scan with selected high-risk paths traced, not exhaustive semantic verification of every Ash action or native helper.

## Durable authority is centralized; replicated clients are not replicated storage

Marshall uses `AshPostgres.Repo` (`marshall/lib/marshall/repo.ex:2`), with PostgreSQL 18.6 minimum declared at line 19. Production Overalls declares one PostgreSQL server on loopback and `fsync`, `full_page_writes`, `synchronous_commit=on` (`fleet/hosts/overalls/configuration.nix:123`, `:141`); its Marshall deployment declares one replica (`fleet/hosts/overalls/services.nix:130`). Dungarees explicitly excludes a local Marshall/database (`fleet/hosts/dungarees/configuration.nix:28`). No PostgreSQL standby or WAL shipping was found in these deployment bindings. Shared-database application replication must therefore not be described as database high availability. Inception separately embeds PostgreSQL with the same three durability settings (`nix/domains/artifacts/guest/inception/default.nix:68`, `:85`).

Serving connections explicitly demand a primary, synchronous commit, 15-second idle transaction and TCP failure bounds plus a one-second client-connection check (`marshall/lib/marshall/operations/runtime_config.ex:144`). These settings constrain recovery after client loss; they do not establish power-loss durability or an end-to-end recovery deadline. `Repo.answers?/0` probes a live trivial query and classifies database failure as inconclusive rather than absence (`marshall/lib/marshall/repo.ex:23`). The distinction is essential for a workload oracle: a timed-out read cannot prove that a mutation was rejected.

`Ledger.transaction/2` invokes an Ash transaction and maintains an outer commit scope; deferred callbacks flush only after a successful outer result outside a database transaction (`marshall/lib/marshall/compute/ledger.ex:21`, `:34`, `:71`). Host/capacity serialization uses `FOR UPDATE` rows (`:133`). The v4 host exchange authenticates session/epoch, ingests physical outcomes and capacity, acknowledges command delivery, confirms drains, selects validated commands, and returns outcome acknowledgements inside the credential-owned transaction (`marshall/lib/marshall/compute/provisioner_control.ex:154`, `:166`, `:174`, `:228`). Outcomes replay only when host and full observation match; conflicting IDs or sequences roll back (`marshall/lib/marshall/compute/outcomes.ex:30`). Valid old observations are historical evidence and cannot undo newer generation/placement intent (`:68`).

The primary fault cut is commit followed by reply loss. A retry must observe retained operation/receipt identity, not issue a new execution generation merely because the transport failed. Capacity holds and current placement must agree with those receipts through database restart and simultaneous old/new exchanges.

## Work queues accelerate durable intent

Oban uses PostgreSQL notifications and the shared Repo; configured queues include default/provisioning/mail/maintenance and a paused, single-concurrency certificate queue (`marshall/config/config.exs:47`). A Compute operation retains pending/acknowledged/completed/cancelled delivery states, with cancellation explicitly insufficient to establish physical absence (`marshall/lib/marshall/compute/operation.ex:68`). Dispatch only hints the host; periodic Lilly exchange and the AshOban schedule rediscover durable pending operations (`marshall/lib/marshall/compute/dispatch.ex:3`, `:13`).

Control hints are nondurable acceleration. They use the caller's transaction connection and subscribers must reread database authority; lost hints have backstop reads and notifier recovery forces resync (`marshall/lib/marshall/control/hints.ex:5`, `:60`, `:93`). Test histories should suppress notifications, repeat jobs, kill a dispatcher, and partition one Marshall replica while preserving database state. The oracle belongs to durable operation progress and current authority, not notification delivery or job completion. Other durable Oban workflows—mail, certificates, cloning, retention—need the same side-effect-versus-job boundary audited individually; this pass did not trace every one.

## Lilly holds two durable state tracks plus native ownership

Lilly's store is a host-bound latest-intent delivery cache, not physical lifecycle authority (`lilly/lib/lilly/control/CONTRACTS:1`). Its independently versioned format remains v3 even though host control is v4. `Store.accept/2` validates immutable placement identity, orders revisions lexicographically by execution epoch/generation, keeps newer intent when older delivery arrives, and rejects equal-revision changes (`lilly/lib/lilly/control/store.ex:29`, `:44`, `:228`). The persistent identity binding prevents a different host/version adopting existing commands (`:11`).

File publication writes an exclusive private stage, syncs contents, publishes through a lock-owning child where a native lock exists, then syncs the directory (`lilly/lib/lilly/host/private_files.ex:36`, `:49`, `:83`). Its contract explicitly treats failure as uncertain publication, not proof the old file remains. Runtime rereads matching or newer durable intent before adding a command acknowledgement (`lilly/lib/lilly/control/runtime.ex:863`, `:888`). Consequently the in-memory `durable` map and pending acknowledgement list are reconstructible accelerators; their disappearance must not lose accepted intent.

Actor execution journals retain attempted/running epoch/generation, stable physical outcome ID/sequence and an acknowledgement bit. A validated outcome is persisted before delivery; identical facts preserve ID and sequence, and an old acknowledgement cannot clear a newer outcome (`lilly/lib/lilly/vm/journal.ex:95`, `:145`). Deleted commands retire only after durable acknowledgement of matching cleanup, while identity tombstones remain (`lilly/lib/lilly/control/store.ex:230`). Lifecycle envelope mutation requires a live OS lock, reload, Ash transition and one durable state/revision file (`lilly/lib/lilly/lifecycle/journal.ex:6`). Legacy diagnostic bytes are separately archived before v2 publication and do not acquire state authority (`:107`).

Transfer persistence is similarly outside portable guest data: snapshot pointers precede journals and become bound; missing bound state must not reset authority (`lilly/lib/lilly/transfer/snapshot_index.ex:10`). Destination imports durably record a local nonce before receiving, retain one exact stream, and bind destination-local GUID once (`lilly/lib/lilly/transfer/import_journal.ex:11`, `:28`). Hosted emulation can exercise metadata/replay logic, but real ZFS receive/resume, GUIDs, tombstones, native locks and independent VMM lifetime require native observation.

## Volatile authority projections must fail closed on expiry and restart

`OverallsProtocol.View` owns protected ETS tables with per-key writer claims, atomic row replacement and monitor-based row removal (`protocol/lib/overalls_protocol/view.ex:36`, `:94`, `:135`, `:182`). Rows and indexes are empty after view restart. Reader lookup rechecks each row's current terms, avoiding stale index membership (`:67`). Versions increment inside a running view; initialization resets the counter to zero (`:98`). The contract's “greater than any earlier one” needs an explicit lifetime interpretation if any consumer retains a version across view restart. This is an open contract-scope question, not a demonstrated consumer defect.

Audi DNS publishes whole validated snapshots with monotonic revision and deadlines based on request start; equal-revision changed entries conflict, late replies do not refresh, and route expiry remains independent of snapshot freshness (`audi/lib/audi/dns/directory.ex:54`, `:85`, `:109`). TLS certificate/private-key generations live only in memory and a store restart removes published identity until reinstallation (`audi/lib/audi/tls/store.ex:106`, `:128`). Lilly legacy owner metadata is a bounded ETS fallback with five-minute expiry and exact execution identifiers; durable command ownership wins (`lilly/lib/lilly/network/owner_cache.ex:13`, `:47`).

Galileo has no pushed state and requests never queue/retry; lost connection is an authority outage (`galileo/lib/galileo/control.ex:3`, `:78`). Porsche rereads management state on demand (`porsche/lib/porsche/control/link.ex:30`), leaving durable requests in Marshall. These are suitable hosted timing properties: suspended writers, reordered hints, stale renewal replies, table/process restart, and expired route/lease checks. The native forwarding effect still requires a real connector/guest to establish physical closure.

## Disposable public caches differ from retained accounting

Brady admits anonymous GETs and explicitly public fresh responses only, separates scheme/origin/port/path/Vary identity, and excludes credentials/query ambiguity (`brady/lib/brady/cache/policy.ex:19`, `:35`, `:76`). Cache commit checks exact body length, syncs body, closes it, writes synced metadata, atomically renames the object directory and only then indexes it (`brady/lib/brady/cache/store.ex:245`). Restart rebuilds an index only from bounded, validated complete body/metadata pairs; unexpected data disables startup (`:592`). Active readers prevent eviction; only confirmed removal decrements retained budget (`:472`). Pressure hysteresis can deny writes while preserving objects (`:464`). No containing-directory fsync appears in this cache commit, so process-restart completeness is a stronger evidenced implementation claim than host-power-loss retention. Disposable-cache loss may be acceptable; partial or unauthorized reuse is not. Nix gives Brady a native ZFS cache and fresh pressure observations (`nix/domains/system/brady/default.nix:25`, `:52`).

Enrico persists Git mirrors but retains attempt receipts only in GenServer maps, capped at 1,024; restart/eviction ends local replay retention and Marshall retains retry/audit intent (`enrico/lib/enrico/manager.ex:58`). Existing mirrors retain old default heads and fetch refs atomically; new mirrors clone to `.new` before native-locked publication (`enrico/lib/enrico/git.ex:47`, `:66`, `:82`, `:106`, `:260`). The entire refresh spans several Git/native calls, so interruptions after successful ref update but before reported success deserve targeted observation. Native locks prevent overlapping writers; the cache quota is 100 GiB by default (`nix/domains/system/enrico.nix:26`).

Ziggy's opposite policy is retained bounded accounting. Admission fsyncs a metadata slot and directory before provider effect, reserving completion space; uncertain writes fence admission and recovery never replays inference (`ziggy/lib/ziggy/spool.ex:87`; effect ordering at `ziggy/lib/ziggy/http.ex:411`). Unfinished recovery becomes interrupted/unknown, not successful zero usage (`spool.ex:201`, `:240`). Reporter retries only immutable completions and removes a slot after exact Marshall acknowledgement (`ziggy/lib/ziggy/reporter.ex:35`). Source SLO checkpoints are fsynced before acknowledged completion removal (`ziggy/lib/ziggy/slo_checkpoint.ex:112`). Marshall locks the request and atomically records first completion plus aggregate totals, with an advisory lock per aggregate bucket; exact canonical replay returns acknowledgement without recounting (`marshall/lib/marshall/inference/requests.ex:121`, `:137`; `totals.ex:6`, `:23`). Commit/reply loss, slot-removal/checkpoint cuts and credential rotation are especially valuable combined histories.

## Independent measurement and diagnostic custody

Request accounting is its own source-local Rust checkpoint, not business/execution authority. Each transition validates immutable source lifetime and nondecreasing totals, writes/syncs a private stage, renames and syncs the directory; uncertain writes poison until reopen (`nix/domains/system/otel-guest/receiver/src/durable_slo.rs:518`). Recorder admission/finish replies follow those transitions; producer death/deadline reconciliation settles pending measurements (`request_recorder.rs:305`, `:324`). Elixir separately fsyncs recording-quality markers, marks uncertain RPCs as gaps and only resumes after recorder and marker agree (`elixir/request_accounting/lib/overalls/request_accounting/producer/server.ex:149`, `:163`). Nix supervises each source recorder separately with private StateDirectory (`nix/domains/system/otel-fleet/request-recorder.nix:54`).

Routine diagnostic spans have a volatile 256-slot ETS queue, so routine enqueue is not durable custody (`elixir/diagnostics/lib/overalls/diagnostics/processor.ex:68`). Committed custody uses an independent SQLite WAL/FULL spool transaction; admission atomically inserts immutable batch and pending row, while downstream delivery deletes only pending (`elixir/diagnostics/native/spool/src/lib.rs:333`, `:483`, `:582`). Retention expiry, not Tempo ACK, removes archive custody. Collector trace queues independently declare fsync and unlimited retry (`nix/domains/system/otel-fleet/default.nix:206`, `:489`). Fluent Bit tail/journal cursors and spool storage likewise use full sync (`nix/domains/system/logging/default.nix:144`, `:156`). Test application progress while all these stores fail; never use missing trace delivery as proof of failed business commit.

## Backups and guest-local state create additional publication boundaries

Backup journals/status use file and parent fsync around atomic replacement (`nix/domains/system/backups/common.py:53`). Host ZFS snapshot cleanup intent records nonce/dataset GUID before snapshot creation, then records snapshot GUID (`host.py:193`). Cleanup must prove retained identity and nonce, and preserve uncertainty (`host.py:108`). A host recovery point publishes only after component captures and confirmed cleanup, uploads the manifest, records its ID, marks completed, then runs retention (`runtime.py:200`). Retention validates manifest references before forgetting and protects referenced component snapshots (`restic.py:256`). PostgreSQL capture is a custom logical dump plus archive listing/checksum, not synchronous replication or continuous WAL recovery (`postgres.py:125`). Cross-component capture is sequential, so a completed host manifest must not imply a globally simultaneous PostgreSQL/guest-disk snapshot.

Guest terminal session IDs, create receipts, ring scrollback and viewer queues are in memory, surviving disconnect but not daemon/guest restart (`nix/domains/artifacts/terminald/src/session.rs:63`, `:99`, `:141`). Editor workers are separately identified by native systemd unit/description and can be rediscovered after broker restart (`nix/domains/artifacts/vscode-web-broker/src/main.rs:605`). Lyra SSH runtime state syncs atomic replacement (`lyra/src/ssh_files.rs:39`); guest account reconciliation holds an exclusive lock through account changes and journal commit (`lyra/src/bin/overalls-ssh-authorize.rs:325`). Workspace source persistence precedes accepted reply and checkout publication/done marker are separate restart cuts (`lyra/src/workspace_receiver.rs:571`, `:613`). Native guest journals/passwd/unit state must be observed alongside Marshall account authority.

## Candidate observation feasibility and open questions

- **Hosted:** real PostgreSQL plus application processes can check commit/reply-loss idempotency, transactional outcome/aggregate conservation, durable queue rediscovery, volatile View invalidation, lease/snapshot expiry, Ziggy accounting, Rust checkpoint/spool reopen, and backup manifest/reference logic against a local Restic repository. Synthetic outcome histories prove database rules only (`marshall/test/marshall/compute/clone_restoration_history_test.exs:10`).
- **Emulated host:** retain production journal codecs, native locks and file publication while supplying controlled host observations. Inject ENOSPC, corrupt/truncated files, late acknowledgements and restarts. Clearly label fabricated physical outcomes; they cannot establish ZFS lineage, guest fsync or VM isolation.
- **Native:** use KVM/ZFS NixOS tests to observe physical VMMs/disks, transfer receive, descendant-held locks, guest boot identity, account reconciliation and backup cleanup. Existing fixtures include delayed-outcome journal histories (`lilly/test/vm/journal_test.exs:14`), Ziggy saturation/reopen (`ziggy/test/spool_test.exs:53`), view restart (`protocol/test/view_test.exs:139`), and real recorder commit/reply cut (`nix/verification/tests/machines/otel-request-recorder/CONTRACTS:1`). Their presence does not establish current passing execution.
- **Open [unvalidated]:** exact acceptable database/backup RPO and restore-consistency expectations; View version comparison across process incarnations; Enrico reported-failure semantics after successful partial refresh publication; power-loss behavior of disposable Brady directories; effective retention/latency under full quotas; and which native facilities the hosted harness can actually expose. Do not substitute documentation, process restart, or filesystem mocks for power-loss/device evidence.
