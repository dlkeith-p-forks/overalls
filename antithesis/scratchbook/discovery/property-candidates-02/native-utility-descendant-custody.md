# native-utility-descendant-custody

P0; high confidence; safety. Planned Antithesis `Always` message: **"Native utility descendant custody blocks a second mutation until retirement"**. For a particular stable lock inode, a second exclusive mutator may begin only after the first utility and every adopted descendant have exited or remain fenced under their inherited lock. Check actual descendant PIDs and inode lock contention; caller death, leader exit, a port-close indication, and command result are not release proof. The [fresh assertion scan](../../existing-assertions.md) finds this assertion **missing**. `Always` is appropriate at every competing acquisition and command completion observation.

Source and claim: `lilly/lib/lilly/host/lock.ex:41-69,90-113` waits for a post-flock nonce and confirmed helper exit. `lilly/native/host-lock/src/lib.rs:282-304,334-405` establishes a subreaper, parent-death fence, inherited descriptor, private-group kill and descendant reaping. `lilly/native/source-export/src/lib.rs:209-210,415-441` applies the same custody rule to transfer senders. A child that creates a new session is a useful discriminator: process-group kill alone would miss it, while the inherited descriptor and adopted-child reap should retain custody. These are source contracts to test, not current passing execution. `lilly/test/host/locked_command_test.exs:233` and native helper tests establish test presence; the historical native actor review reports a scoped pass, not a current Antithesis run.

Workload and oracle: under a real Linux host-lock helper, launch a controlled mutator whose grandchild reports its PID and deliberately changes session, keep it alive past leader exit or kill the BEAM caller/helper, then race a distinct process on the same inode. A workload-owned PID/inode ledger and direct `flock` probe independently establish whether the conflicting effect could start. Reconcile uncertain helper replies by observing descendant death and lock state; do not call a timeout a completed mutation. A `Reachable` branch message **"Native utility cleanup reaped escaped-session descendant"** can mark the meaningful rare cleanup outcome. No credentials or utility arguments belong in telemetry.

Value menu: ordinary/grandchild/new-session child; caller stop, helper death, leader exit, output overflow and timeout; same versus different inode; shared versus exclusive lease; 1/2/8 contenders; short and near-deadline descendants. Hosted Linux can exercise process/flock custody. Real ZFS mutation and Firecracker descendant fencing require native machine execution; a TCG executor cannot establish those boundaries. Open question: can the hosted container expose adopted descendants and stable inode identity after forced helper death? If not, retain the same oracle in the native suite.
