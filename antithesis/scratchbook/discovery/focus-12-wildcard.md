# Wildcard discovery

This pass looks for missing concepts and emergent interactions beyond the other eleven lenses. Its strongest finding is that elapsed authority, independent measurement, and native custody are compositional obligations: a correct component can receive an already-aged grant, publish a locally complete recovery point, or finish its direct child while another layer still holds authority or physical resources. These are hypotheses to falsify, not declarations that the system is defective.

The inspected scope includes Marshall, Lilly, Audi, Brady, Enrico, Galileo, Porsche and Ziggy; the shared protocol, accounting and diagnostics libraries; Lyra and guest/native helpers; browser launch code; Nix service topology; and backup coordination. Root/component guidance, architecture overview and decision index, relevant ADRs, ancestor/local contracts, the research skill, analysis methodology and claim-validation guidance were consulted. Only Focus 12's wildcard directives were read from discovery guidance. The other focuses' detailed checklists and retired `antithesis/` material were not consulted. HEAD matches the stated baseline; the worktree already contains the authorized reset and documentation reconciliation changes. No repository changes were made by this pass.

## 1. Authority can age while an independent observer blocks

The observability split is a valuable architectural distinction, but independent ownership does not imply independent latency. `Overalls.RequestAccounting.Producer.admit/2` performs a synchronous five-second GenServer call (`elixir/request_accounting/lib/overalls/request_accounting/producer.ex:57–64`); recorder RPC allows one second to connect and another to receive (`recorder_rpc.ex:26–46`). The producer may also synchronously recover gap markers and perform multiple recorder operations (`producer/server.ex:149–169`). Saturation therefore affects callers even when the ultimate answer is `:unrecorded` and work is permitted to continue.

Galileo obtains Marshall authorization before this wait (`galileo/lib/galileo/http.ex:99–102`). Only afterward does `Upstream.stream/2` create a new deadline from the original TTL (`galileo/lib/galileo/upstream.ex:71–85,426–428`). The protocol permits TTLs from 500 to 5,000 milliseconds (`protocol/lib/overalls_protocol/integration.ex:163–176`). Audi gateway catalog handling, by contrast, anchors expiry to time before its request (`audi/lib/audi/control/client.ex:184–199`), and Ziggy subtracts admission/spool elapsed time before starting its lease (`ziggy/lib/ziggy/http.ex:410–417`). These differences suggest a concrete cross-service test.

Hypothesis: stall accounting after Galileo authorization, revoke the integration during that stall, then release the recorder. No body pull or credential-bearing upstream effect may begin from a grant whose original budget is exhausted. Observe the real upstream accept/read boundary and Marshall renewal history, not merely the final HTTP status. This discriminates aged authority from ordinary upstream failure. Enrico has a second composition seam: its single manager admits measurement inside `handle_call` before replying (`enrico/lib/enrico/manager.ex:89–123`), so an observer stall may delay unrelated status/replay calls. Porsche admission precedes command execution (`porsche/lib/porsche/observability.ex:80–88`), Audi admission precedes private forwarding (`audi/lib/audi/private/front.ex:59–64`), and Brady wraps eligible attempts (`brady/lib/brady/proxy.ex:141–163`). Observer-loss testing should preserve outcomes and examine latency/cancellation separately.

## 2. Logical generation and physical boot are intentionally different identities

Overalls does not have one universal execution version. Lilly can adopt a newer logical generation while preserving the same physical boot challenge (`lilly/lib/lilly/vm/boot.ex:64–83`). The adoption contract explicitly says this does not establish guest readiness or authorize another boot. `Boot.current/3` then requires exact placement, epoch, generation and running intent (`boot.ex:95–115`). Guest trust receipts use placement, epoch, boot challenge, nonce and trust digest without a logical generation (`lilly/lib/lilly/vm/guest_trust.ex:94–108`). Workspace delivery journals add generation to the same physical identity (`lilly/lib/lilly/vm/workspace_source.ex:245–275`).

This is a deliberate asymmetry, not an inherently stale proof. It creates a valuable history: continue a real boot through newer intent, retain an outstanding old-generation workspace delivery, replace the actor or control connection, and deliver delayed trust/workspace replies. The same boot must remain physically continuous, but an old logical receipt must not settle the new journal generation. Verify PID plus kernel start time, challenge continuity, exact current intent, and recipient-specific acceptance. Checking only that the VM remains running would miss both erroneous boot replacement and receipt rebinding.

Image capability is another independent axis. Fresh source-bearing starts validate manifest version/capability before host effects (`lilly/lib/lilly/vm/driver.ex:347–364`), whereas retained restart verifies its portable bundle without consulting/recreating image artifacts (`driver.ex:367–375`). A current catalog entry does not prove an old writable disk acquired newer receiver or identity semantics. ADR-0157 lines 108–119 explicitly retains this migration boundary.

## 3. A personal origin is not a security boundary inside a shared VM

Durable guest identities provide permanent UUID/UID/name/home assignments (`marshall/lib/marshall/accounts/guest_accounts.ex:10–14,72–87`; ADR-0158 lines 32–50). Editor workers are launched under that exact account and current release, and use `KillMode=control-group` (`nix/packages/vscode-web-broker/src/main.rs:645–659`). Yet repository checkouts are intentionally shared: directories become 0777, regular files 0666, executable files 0777, while symlinks are skipped (`lyra/src/workspace_receiver.rs:663–689`). Every guest login account receives passwordless sudo (`lyra/src/bin/overalls-ssh-authorize.rs:276–279`); guest Git explicitly trusts `/workspace/*` (`nix/packages/guest/private-services.nix:86–90`). Editor workspace trust is disabled through its startup arguments (`nix/packages/vscode-web-broker/src/main.rs:553–571`).

The missing conceptual distinction is platform account authority versus isolation from a collaborator already authorized to write the same guest. A workload should exercise retirement and fresh same-email registration while another writer deliberately mutates the shared checkout and keeps its own processes alive. Expected refusal is renewed platform SSH/editor/terminal access for the retired identity; shared bytes and another writer's processes may legitimately survive. Do not assert that retirement erases all work or makes the VM hostile-code safe for remaining writers. Those assertions would contradict the actual guest authority model. Native tests should separately verify that generated account identity, current editor origin, process ownership and platform refusal remain exact despite mutable shared workspace content.

## 4. Source identity is immutable while the selected checkout can move

The browser minimizes a URL to provider origin/path and preserves raw spelling for server refusal (`browser/common/launch.mjs:35–46`). Marshall stores a bounded signed-session capture, derives admission identity from actor plus canonical source plus visit, and creates the VM before signing a completion receipt (`marshall/lib/marshall_web/pending_launch.ex:23–33,67–86`; `launch_live.ex:50–67`). Guest resolution occurs later. Named references select the longest advertised match, and change heads can resolve through provider-specific refs/APIs (`lyra/src/workspace_checkout.rs:36–123`). The persisted source identity is not the resolved commit identity.

Consequently, replay equivalence means the same launch visit returns the same VM; it does not mean two independently launched visits see identical commits. Move a branch between capture, authenticated admission, first clone attempt and retry. Crash after VM commit but before cookie clearing, and after checkout rename but before its durable done marker (`lyra/src/workspace_receiver.rs:612–634`). Require one VM per authorized visit, no replacement source, and no additional clone after completed checkout (`workspace_receiver.rs:570–594`). Observe the actual guest HEAD and invocation history rather than predicting a commit from the source URL alone.

Readiness is deliberately separate: the workspace service must remain outside required guest-ready units so provider availability cannot block VM readiness (`nix/packages/guest/private-services.nix:57–68`). Tests therefore need distinct observables for “machine ready,” “source delivered,” and “checkout complete.” Using readiness as a checkout-success oracle would manufacture confidence in the launch journey.

## 5. A complete host backup is a recovery graph, not a global snapshot

The coordinator inventories guests once, then snapshots/uploads/releases each guest in turn, captures PostgreSQL afterward, and finally captures host state and locked pool metadata (`nix/modules/backups/runtime.py:122–197`). Lilly copies ownership/import/tombstone metadata under the pool lock (`lilly/lib/lilly/backup.ex:181–205`). These local captures can each be correct while representing incompatible moments. ADR-0070 explicitly acknowledges different timestamps and requires historical control-plane/disk reconciliation in quarantine (lines 120–125), with no automatic production reconciliation (lines 86–102).

A concrete campaign should resize, relocate, delete and create guests during a slow upload. A completed manifest may legitimately contain older disk bytes and newer metadata, or a later ownership record for a guest created after inventory. Its publication must not imply these components constitute an executable current fleet. Restore only into the documented fresh private target, verify each component independently, and preserve disagreement as a recovery obligation rather than quietly serving restored authority.

Identity rollback makes the graph more subtle. A database captured before a later UID allocation cannot know that a surviving disk now contains `/home/u<uid>`. The allocator's noncycling sequence protects the current timeline; restoring an older sequence loses later reservations. ADR-0158 lines 106–110 explicitly calls older-database/newer-disk authority unsupported until UUID/UID reservations and sequence are reconciled. A test should demonstrate refusal or quarantine, not invent automatic safe historical activation. This boundary spans backups, database allocation, SSH, personal editor origins and retained disks.

Backup uncertainty also has a pool-wide consequence. A snapshot journal outside ready/cleaned refuses ownership expectations (`lilly/lib/lilly/host/backup_snapshot.ex:33–61`); expectation traversal halts on any placement failure (`lilly/lib/lilly/transfer/snapshot_ownership.ex:19–29`), and pool observation requires those expectations (`lilly/lib/lilly/host/zfs_dataset.ex:814–818`). Kill a producer after native snapshot creation but before ready publication while Marshall is unavailable. Guests may remain physically alive while allocation evidence disappears for their whole pool. Require independent cleanup to restore observations without fabricating credit or restarting guests.

## 6. “The command finished” has several incompatible physical meanings

Native custody is richer than process-group cleanup. Enrico's Git owner becomes a subreaper and waits for adopted descendants across groups/sessions before confirming cleanup (`enrico/native/git-owner/src/main.rs:138–160`). Lilly host-lock likewise retains its unreaped leader through signaling and reaps descendants before returning a command result (`lilly/native/host-lock/src/lib.rs:282–299`). The editor broker's helper command instead returns immediately when its direct child exits and kills the new process group on timeout (`nix/packages/vscode-web-broker/src/main.rs:212–229`); actual editor workers are separately owned by systemd cgroups. These are different containment strategies with different proof obligations.

Exercise a helper whose direct child exits successfully while a grandchild holds stdout, a lock, an open disk or a socket; have another grandchild create a new session. Verify resource custody at the native effect boundary before granting a replacement owner. This is not a claim that the editor broker accepts untrusted executables: its tools are fixed. It tests whether ordinary tool behavior, interruption and service restart compose with the promised ownership boundary. Distinguish helper completion, descendant retirement, systemd unit completion and lock release in the oracle. A command status alone cannot establish all four.

## 7. Build isolation participates in lifecycle correctness

Deletion can depend on an apparently unrelated Nix build. ADR-0144 records locked guest mounts copied into user namespaces, which prevented destroy even after host unmount. Current deployment removes Lilly pool mounts inside the daemon's own slave namespace and directs host/root builds through it (`nix/modules/lilly.nix:276–299`). The decision still requires daemon restart when a pool is remounted after daemon startup (ADR-0144 lines 38–52).

The interesting history is pool remount or runtime pool change interleaved with daemon/build startup and fenced delete. Verify the actual build namespace has no guest mounts and that deletion observes dataset absence before releasing capacity; inspect namespaces pinned by descriptors as well as live processes. The wrapper suppresses individual unmount failures (`lilly.nix:292–295`), making native namespace observation particularly useful. A fake successful `umount` or a container lacking real user/mount namespace behavior cannot establish this property.

Brady adds a nearby resource coupling: native pressure counts both pool and guest-parent headroom and subtracts pending writes (`brady/lib/brady/cache/store.ex:104–145`). Stale evidence makes the cache read-only while retaining objects. Backup snapshots, cache writes, guest growth and Nix store work can all change shared physical headroom; independent quotas are ceilings rather than reserved free capacity (`nix/modules/nix-gc.nix:6–8`). Test mixed histories with stalled pressure sampling, retained readers and guest growth, using native allocation facts instead of summing configured quotas.

## 8. Supervision is part of the authority protocol

One initially suspicious scenario is actually constrained by production topology. Protocol View restart clears ETS rows, owners and subscribers (`protocol/lib/overalls_protocol/view.ex:94–112`). A private subscriber therefore cannot recover notifications by relying on the old subscription. Lilly's real `:rest_for_one` tree places Execution before Runtime and connectors (`lilly/lib/lilly/application.ex:45–50`), so view failure also retires dependent authority owners. Private admission subscribes and re-resolves before granting (`lilly/lib/lilly/private/server.ex:191–198`), and Audi kills a request on subscription loss (`audi/lib/audi/private/guard.ex:25–30,60–70`).

A harness that restarts View alone while retaining subscribers creates a topology the production application does not use. Test the real supervisor, then assert socket closure, old-request retirement and fresh unproven authority before subsequent admission. This preserves the important negative finding while exposing future child-order regressions. Deployment similarly separates durable migration from service activation: migrations run before switch (`nix/modules/auto-update/runtime.py:1020–1024`), and failed activation attempts service restoration without reversing schema changes. “Last healthy release” is history, not proof that old schema authority was restored.

## Assumptions

Source observations describe current mechanisms and intended contracts; no runtime, type, property, NixOS or Antithesis checks were executed by this pass. Finite TTLs are tested with actual elapsed boundaries, not arbitrary sleeps alone. Native containment/storage properties require real kernel and ZFS evidence; a reduced harness can cover corresponding models but must label that limit. Architecture impact is none: this report proposes test hypotheses and changes no accepted decision or implementation.

## Open Questions

Does Galileo preserve the original authorization age through accounting admission and initial upstream connection under delay? Which fixed editor/helper subprocesses can leave descendants beyond their direct child's lifetime? What recovery procedure reconciles post-backup guest identity reservations before any historical authority is served? Can pool remount histories recreate locked guest mounts in current Nix build namespaces? These require discriminating execution evidence; documentation claims alone do not settle them.
