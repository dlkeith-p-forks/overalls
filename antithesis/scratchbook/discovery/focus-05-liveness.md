# Examined scope and evidence limits

This independent pass examined repository code, accepted and superseded ADRs, architecture overview, selected tests and local Git history. It followed Marshall admission, dispatch, host reports, crash recovery, clone/relocation and terminal reconciliation; Lilly runtime, actors, journals, readiness and native lock owners; shared control transport; Audi DNS/TLS/stream authority; Brady cache recovery; Enrico refresh ownership; Galileo/Porsche/Ziggy request handling; Lyra guest supervision; native terminald; independent diagnostics/request accounting; and Nix backup/updater supervision. Browser terminal recovery and current guest/editor identity decisions were included. No retired `antithesis/` artifact was read, no external claim or issue tracker was consulted, and no source was changed. Tests mentioned below were inspected, not executed by this pass. Historical execution claims remain scoped evidence, not proof for the current revision.

The repository promises several kinds of progress, but no unconditional end-to-end completion bound under arbitrary faults. Distinguish observable terminal settlement from successful execution: cancellation, conservative failure, exhausted retries and permanent refusal can be intended completion states. Safety obligations such as retaining uncertain reservations and refusing expired authority continue during faults; successful progress usually requires a healthy quiet period, current authorization, compatible releases, storage capacity and sufficient scheduler service.

# Control recovery and freshness have different clocks

`protocol/lib/overalls_protocol/control/client.ex:22-27,424-450` uses full-jitter reconnect delays of 1–1,000 milliseconds initially, doubling to a 4,000-millisecond ceiling. Draining reconnects within a 500-millisecond ceiling; unsupported-version reactions stop the client. A reconnect delay is not a complete recovery deadline: DNS/TLS connection, hello/welcome, database readiness, owner resynchronization and scheduled request execution must also complete. Opening connections is asynchronous, allowing status and request refusal while a connect hangs. Pending calls have deadlines and resolve disconnected/unproven rather than being secretly replayed (`:request` contract at lines 52-57). Each application must discover durable work again or retry its own idempotent intent.

Lilly separately maintains one exchange in flight, with 1/2/4-second base retry delays **plus 1–500 milliseconds of jitter** (`lilly/lib/lilly/control/runtime.ex:818-948`). Its one-second tick, completed-sample dispatch and host-command hints shorten latency, but report collection, transport backoff and outcome ingestion can still delay a report. Freshness is not refreshed by replaying an uncertain sample. `marshall/lib/marshall/compute/host_liveness.ex` classifies shared durable host state; production defaults are **5 seconds for capacity** and **60 seconds for authority** (`marshall/config/config.exs:136-137`). A late report can preserve existing ingress/terminal/inference authority while new capacity admission refuses. Lilly's own readiness is stricter in another direction: authenticated control, terminal authority, a report delivered by this runtime within **15 seconds of sampling**, and a completed observation of every current placement/epoch/generation (`runtime.ex:1034-1062`). Readiness is therefore a conjunction, not a synonym for socket connectivity.

ADR-0141 treats PostgreSQL notifications as committed hints and requires resync after notifier isolation. Lost hints do not remove the durable pending operation; `marshall/lib/marshall/compute/dispatch.ex` leaves it discoverable by exchange and AshOban scheduling. A useful property is: after reconnect and a stable healthy interval, every admitted discoverable intent is acknowledged or reaches an explicitly permitted refusal, without treating receipt of a hint as progress.

# VM recovery is bounded, conservative and evidence-driven

ADR-0017 claims actor recovery while systemd preserves VMMs. Restored actors remain paused until authenticated control and matching pool identity. Journals record attempts before physical effects and outcomes before delivery. A launch-attempt marker without proven completion intentionally can require a new explicit start; automatic repeat is prohibited. This is a safety/progress tradeoff, not an automatic-recovery bug premise.

`lilly/lib/lilly/vm/actor.ex:145-157,500-545` routes observations through shared Cadence: one executor task at a time, ticks dropped during work, and one prompt follow-up for superseding intent. The comment identifies the concrete fairness hazard: treating every unchanged runtime cast as a request would run reconciles back to back and continuously hold placement/pool locks. The current distinction should be tested against competing relaunch, cleanup and receive work, including a sustained stream of unchanged casts. Busy journal/VM/network locks defer rather than rewrite an authoritative outcome. Failed deletion retries exponentially up to **30 seconds**, preserves the fence and resets on a new command (`lilly/lib/lilly/vm/delete_retry.ex`, actor finish path).

Readiness can wait for minutes, while roster bootstrap itself needs boot evidence. The independent per-tick boot probe in `actor.ex:569-590` addresses that circular wait while the main reconcile is in flight. An execution proof has a **2-second** backstop without an exact armed native watcher, or **30 seconds** with that watcher (`actor.ex:16-17,595-602`). These are proof-expiry ceilings, not guest startup objectives. `lilly/lib/lilly/vm/driver.ex:484-543,932-972` waits outside mutation locks, then revalidates exact authority and remaining original deadline; bounded lock retries cannot create a fresh deadline.

`marshall/lib/marshall/compute/outcomes.ex:251-330` allows at most **three automatic starts per ten minutes**. Future timestamps remain charged across a backward database clock jump. Stale telemetry holds recovery pending and fresh accepted reports re-decide it; exhausted budgets, a measured shortfall or unavailable durable workspace-source capability refuse restart and release only proven compute. Consequently, test “fresh report wakes eligible pending recovery,” not “every crashed VM always starts.” ADR-0126 separately claims a **35-second total database connection-reclamation** fixture after observed lock queues and client-machine loss, preserving a healthy 20-second query. Production 1-second disconnect polling and 15-second TCP limits are mechanisms, not independent universal SQL deadlines.

# Work queues and overload do not establish general fairness

Marshall's Oban defaults expose provisioning concurrency 10 and maintenance concurrency 2; many resource schedulers run every minute (`marshall/config/config.exs:49-63` and Compute resource triggers). Those settings bound workers, not queue delay. `marshall/lib/marshall/terminal/reconciler.ex:36-70` deliberately provides cursor continuation: ten VM jobs per transaction, one pending kill/opening per VM step, and progress beyond a failing request. This is an unusually concrete starvation-freedom claim suitable for a workload containing one permanently failing request alongside later valid requests.

Clone coordination selects the unfinished per-source head by ascending sequence (`marshall/lib/marshall/compute/clone_coordinator.ex:125-130`). Its serialization is intentional: later same-source work may legitimately wait for physical source restoration and cleanup of the head. An observer must distinguish that retained obligation from an abandoned job. Different sources should still make progress once transfer and host resources permit it.

There are two high-value fairness questions rather than established defects. Lilly sends the lexicographically first **16** pending outcomes (`control/runtime.ex:838-840`). Marshall ingests all outcomes before host report/acknowledgements in the same transaction (`compute/provisioner_control.ex:174-205`). A persistently conflicting head can prevent both acknowledgements and new freshness; primary code shows the coupling, but no current reproducible production defect was established. The harness should create lawful conflicting/uncertain histories and verify whether a defined fence or operator recovery resolves them, without assuming malformed data deserves automatic bypass.

Enrico admits at most **eight** active repository refreshes, releases slots on supervised worker completion/death and retains at most 1,024 completed receipts (`enrico/lib/enrico/manager.ex`). The durable Marshall worker has three attempts, 4,200-second uniqueness, a 70-minute worker timeout, and a minute cron that selects at most **100** due repositories without an explicit order or cursor (`marshall/lib/marshall/enrico/worker.ex:3-43`). Its intended refresh cadence is hourly. Under continually due early rows and slow two-worker maintenance execution, the implementation does not itself establish strict starvation freedom for later repositories. Test bounded admitted backlog, slot reclamation after actual worker death, same-attempt recovery and last-good-head preservation; record heavy-load fairness as open rather than assert an invented SLA.

# Satellite progress deliberately ends at lease/refusal boundaries

Audi DNS refresh is complete-snapshot, single-flight, one second after completion, with coalesced hints. Failure preserves original expiry; expired data stays unavailable and unsupported version halts until restart (`audi/lib/audi/dns/replica.ex:45-110`). Snapshot TTL is at most **5 seconds from request start**, not receipt (`dns/snapshot.ex:15-55`). Therefore healing transport cannot alone promise restoration after a terminal version refusal. Audi certificate work likewise preserves the last proven serving generation through inconclusive refresh failures, grants no new route readiness without successful install/SNI probe/acknowledgement, and stops automatic work on explicit version refusal (`tls/fleet_worker.ex:95-105`).

Audi stream renewals distinguish transient transport/non-2xx/late grants from definite refusal: retry up to 250 milliseconds or half the remaining lease, preserve the current deadline, and close on expiry (`authority/renewal.ex`). One source note is stale: `authority/lease.ex:7-15` says five seconds while the runtime accepts TTL through **30,000 milliseconds**, matching later pushed web/SSH lease work. Galileo's Integration codec still admits **500–5,000 milliseconds**; Ziggy's separate request lease permits **30 seconds**, renewing by default after ten seconds and directly killing blocked owners on expiry (`protocol/.../integration.ex:163-192`, `ziggy/lib/ziggy/lease.ex`). There is no single fleet lease ceiling.

Ziggy pulls at one-second cadence with up to 16 active model tasks. A claimed, fsynced provider attempt that dies remains uncertain rather than being automatically claimed again (`ziggy/lib/ziggy/agent_worker.ex:72-78,280-320`). Request progress therefore may terminate as uncertainty; provider success is conditional on live authority and upstream availability. Galileo makes one authorization/upstream attempt and closes on renewal failure. Porsche's wait only observes an admitted request: one-second polling tolerates transient failures until its original deadline, default **120 seconds**; timing out the CLI does not cancel the durable request (`porsche/lib/porsche/runner.ex:62-71,125-160`). Brady cache initialization retries every five seconds and revalidates native mount custody; cache failure is intended to leave proxy listeners available (`brady/lib/brady/cache/recovery.ex:25-76`). Test cache recovery separately from upstream reachability.

# Guest, browser, diagnostics and operations progress

Native terminald explicitly promises that a viewer stalled on read credit cannot retain the shared registry mutex and prevent other sessions creating, attaching, resizing or delivering output (`nix/packages/terminald/src/session.rs:635-647`). Explicit kill must retire a credit-stalled session without waiting for that credit; inspected native tests use actual PTYs and a two-second retirement observation. Browser selected-pane recovery independently retries deferred attachment every 500 milliseconds and tickets every 2.5 seconds; a 15-second attached-socket silence detector seeks a surviving Marshall node (`marshall/assets/js/terminals.js:416-462,1073-1093`). Browser event-loop pauses and `Date.now()` jumps are assumptions to exercise, not evidence of server failure.

Lyra's immutable seed checks guest updates every **120–150 seconds**, waits up to **60 seconds** for executor exit between commands, and waits up to **90 seconds** for candidate registration before restoring the previous executable. Rejected candidates cool down 15 minutes; transient manifest failure must not extend that cooldown (`lyra/src/update.rs:390-525`). A never-finishing command can defer activation intentionally. ADR-0158 requires compatible generated-identity guests and excludes mixed old/new serving; ADR-0155's stopped-only move claims every nonterminal phase can reach a terminal graph state, but actual completion additionally needs full-stream transfer, destination readiness and source cleanup. Graph reachability alone does not verify runtime liveness or a downtime bound.

ADR-0149 removes diagnostic acknowledgements as lifecycle gates. `lilly/lib/lilly/lifecycle/diagnostics.ex` imports retained archives independently, bounded to 128 paths per scan, with continuation every 100 milliseconds and five-second rescan after completion. Refused archives must remain retryable without affecting actor/command/outcome progress. The Rust spool drains successful accepted deliveries eagerly, with network I/O outside its custody mutex and 250-millisecond failure backoff (`elixir/diagnostics/native/spool/src/main.rs:319-350`). Request accounting separately uses a five-second recovery heartbeat and 4,096 pending-ticket cap; worker death settles failure, and recorder loss creates a durable measurement gap (`elixir/request_accounting/.../producer/server.ex`). Healthy measurement publication is not execution authority, and missing history cannot establish a seven-day SLO.

Nix host updates poll after inactivity every ten seconds, retry the same failed candidate at 30-second exponential backoff capped at 900 seconds, reset on a corrective revision, and verify health by an original configured deadline (default 120 seconds). Partial activation retains exact-candidate handoff instead of claiming rollback (`nix/modules/auto-update/runtime.py:943-1044`, `default.nix:138-139`). Quiet periods must include outstanding backoff, builds, migrations and health checks. Backups run half-hourly with stable jitter up to 300 seconds and five-minute cleanup timers; commands default to 7,200-second limits and the service itself has no start timeout. Capture attempts remain independent of PostgreSQL availability and guest flush is best effort (`nix/modules/backups/{timers.nix,runtime.py,default.nix}`). No short backup completion SLA follows from timer frequency. Disaster restore additionally requires operator fencing and explicit identity reconciliation, not automatic admission against restored historical authority.

# Testing feasibility and open questions

Hosted separate containers can expose Marshall/PostgreSQL/control reconnection, asymmetric partitions, all satellite lease protocols, real Unix recorder/spool backlog, Enrico admission and pure browser state. Emulated executors can verify durable scheduling and retry semantics but cannot prove VM readiness, systemd independence, ZFS transfer/recovery or isolation. Native PTY, descendant-custody and Linux namespace tests can run only after the required tenant kernel capabilities are established. Complete Firecracker/KVM, ZFS and systemd guest paths require a demonstrated native-capable environment; preserve NixOS machine checks as separate evidence when unavailable in hosted testing.

Use quiet-period terminal or mid-run recovery checks after observing the admitted pending state. Stop new arrivals where bounded backlog is a premise. Confirm node termination for crash-recovery properties and clock faults for wall-clock freshness/retry cases; both may be disabled by default. Bounds must include service restart, durable reopening and applicable backoff, not just network healing. Instrument per-intent age and progress so a global “sometimes one operation succeeds” cannot hide starvation. Safety checks remain active throughout faults. Open questions are maximum fair backlog, queue arrival assumptions, whether terminal refusal requires operator restart, acceptable combined recovery budget, and native capability availability. No new architecture decision is proposed; this report records claims, mechanisms and verification gaps for subsequent property discovery.
