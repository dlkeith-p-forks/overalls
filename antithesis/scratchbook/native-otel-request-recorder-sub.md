## Production implementation and component assertions

`nix/modules/otel-guest/receiver/src/request_recorder.rs:15` implements closed version-one hello/admit/gap/finish JSON in four-byte big-endian frames, at most 512 payload bytes with unknown-field rejection. `:207` authenticates SO_PEERCRED UID plus exact cgroup-v2 service; PID/start ticks/boot identity fence producer incarnation. `:151` treats unprovable liveness as unknown. `:324` persists admit/gap/finish via Store before reply; `:386` withholds fresh publication unless store/heartbeat/pending/deadline conditions are healthy. `:527` reconciles independently of traffic and logs no frames. CLI is **`src/bin/slo_recorder.rs`**, not `src/slo_recorder.rs`; `:9` validates eight arguments, source, octal mode and checked seconds conversion and exits 2 on refusal.

Local component tests at `request_recorder.rs:642` generate process names/start ticks to prevent `/proc` parse identity shift; reject >512 frames before allocation; reject sibling/prefix/suffix unit names while accepting exact unit descendants. `:664` refuses unknown fields/op, version two and truncated frames; `:686` checks current kernel incarnation alive, inaccessible proc unknown, and changed start/boot identity dead. These are local Rust tests, not machine execution or a production journey. ADR-0136:102 records the underlying Store bounds of 4096 pending admissions and a one-MiB checkpoint.
