## zfs-io oracle and present incompatibility

The intended driver verifies two pools with measured logical whole-pool I/O, `openzfs_zpool_iostat`, dataset-scoped capacity provenance, 1000 ms requested interval, unknown exact interval/latencies/queue/busy/maxima, elapsed collection at least 1000 ms, actual import GUID, nonnegative integer read/write IOPS and bytes/s, and positive capacity no greater than 512 MiB with no VM allocations ([driver:28](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/zfs-io/driver.py:28)). Concurrent direct reads and fsynced random writes occur in `tank/workload` outside Lilly's parent; all four `tank` metrics must be positive ([driver:59](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/zfs-io/driver.py:59)). Malformed output, timeout and actual export/import must make both pools' rates and import identity unavailable while retaining positive capacity; reload keeps permanent GUID, changes import GUID, and a clean sample must recover after every fault ([driver:72](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/zfs-io/driver.py:72)).

**Source-level execution blocker:** the probe calls `Collector.sample/4`, round-trips the capacity report and projects `:io` ([probe:25](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/zfs-io/probe.exs:25)). Current `Collector.collect` explicitly excludes diagnostic counters from control reports, ignores `_native_io` and constructs pools solely through `Pool.report/1` ([collector:46](/home/ghuntley/src/overalls-antithesis-reset/lilly/lib/lilly/host/collector.ex:46)). `Pool.snapshot/1` returns capacity/storage/allocation fields with no I/O ([pool:200](/home/ghuntley/src/overalls-antithesis-reset/lilly/lib/lilly/host/pool.ex:200)); current protocol pool types also exclude I/O ([protocol:7](/home/ghuntley/src/overalls-antithesis-reset/protocol/lib/overalls_protocol.ex:7)). Driver `sample` immediately indexes `pool["io"]["zpool_name"]` ([driver:21](/home/ghuntley/src/overalls-antithesis-reset/nix/verification/tests/machines/zfs-io/driver.py:21)). The suite therefore cannot reach its I/O or fault oracles through this present path. This is inferred from source, not a new executed failure.

The source sampler still exists and preserves import-bound logical interval semantics ([ZFSIO:10](/home/ghuntley/src/overalls-antithesis-reset/lilly/lib/lilly/host/zfs_io.ex:10)); restoring counters to the collector would conflict with accepted ADR-0149, which puts pool I/O in infrastructure export ([ADR-0149:37](/home/ghuntley/src/overalls-antithesis-reset/docs/architecture/decisions/0149-independent-observability.md:37)). Any follow-up should reconcile the suite with that current boundary while retaining native faults and capacity independence.
