## Executable order

The commands below are a plan, not executed evidence. Use this bounded runner for each selected attribute; keep logs private because failed fixture diagnostics may contain synthetic credential material. `--builders ''` fixes execution to this local builder, and explicit `--max-jobs 1` prevents concurrent large suites. `--cores 8` bounds dependency builds, not the number of virtual CPUs a fixture declares. The extra features make the checks schedulable; runtime checks must still pass.

```sh
run_check() {
  local check_name="${1:?one exported check name required}"
  [[ "$check_name" =~ ^[a-z0-9][a-z0-9-]*$ ]] || return 64
  nix eval --raw ".#checks.x86_64-linux.${check_name}.drvPath" > "$campaign_dir/${check_name}.drv" || return
  nix build --no-link --print-build-logs --keep-failed --builders '' \
    --max-jobs 1 --cores 8 --extra-system-features 'nixos-test kvm nested-kvm' \
    ".#checks.x86_64-linux.${check_name}" \
    > "$campaign_dir/${check_name}.build.log" 2>&1
}
```

When Nix already has the matching check output and a **fresh execution** is required, build the documented driver and run its complete default script in a new private directory. Driver realization alone remains unexecuted construction evidence:
