## Conclusion

The universal five-second statement in `audi/lib/audi/authority/lease.ex:7–10` is stale relative to accepted ADR-0142 and current long stream authority. It is a real source-contract contradiction, but **the 30,000 ms generic lease constructor is not evidence of an unauthorized lifetime regression**. A universal five-second assertion or changing every grant to five seconds would contradict the accepted web, ordinary SSH and editor policies.

The accepted policy is class-specific: web and ordinary SSH have up to thirty seconds; editor has a renewable thirty-second maximum with tighter current-identity deadlines; nested streams retain the publication/five-second bound; gateway catalogs and complete DNS snapshots retain five-second freshness. Local expiry always derives from the request-start monotonic clock, and no renewal may revive an expired lease.

There is a separate, evidenced **catalog decoder enforcement mismatch**: `OverallsProtocol.IngressCatalog.decode/1` accepts 5,001–30,000 ms although its own `ingress-catalog-identity` contract and ADR-0142's current catalog policy require at most 5,000 ms. Marshall currently issues 5,000 ms catalogs; this finding does not establish that production ever received or served a longer catalog. Do not weaken this class-specific contract to 30 seconds when correcting the generic lease note.

## Exact findings and future correction

1. **Confirmed stale common lease specification.** Contract `audi-grant-request-deadline`, `audi/lib/audi/authority/lease.ex:7–10`, still says every grant expires within five seconds. Current accepted web/ordinary SSH/editor policies and the intentional constructor migration contradict it. Correct the stable contract's numeric universal claim to the reviewed generic thirty-second envelope while preserving request-start anchoring, trusted/authenticated-only entry, monotonic clock, class-specific tighter policies and all no-resurrection/full-binding rules. Do not merely replace every occurrence of “five” with “thirty”.

   A precise future common contract can state: “A trusted grant MUST expire at `requested_at + ttl`, with a positive TTL no greater than 30,000 ms, never at receipt time plus TTL. Production callers MUST supply an authenticated, class-validated control reply; tighter issuer policies remain web/ordinary SSH/editor at most thirty seconds and nested at most five seconds/the publication's remaining lifetime. All timestamps MUST use this node's monotonic millisecond clock.” An alternative split into separate deadline and caller-precondition contracts is valid if the existing deadline ID remains stable and newly introduced IDs follow owner conventions. The constructor must not pretend to implement tighter class checks it has no input to identify.

2. **Confirmed separate catalog receiver mismatch.** Contract `ingress-catalog-identity`, `protocol/lib/overalls_protocol/ingress_catalog.ex:4–8`, and ADR-0142 `:340–349` retain the five-second cap. Decoder `:23` accepts up to thirty seconds; `Audi.Control.Client.gateway_catalog/1` turns that into a local deadline without shortening it. A syntactically valid empty six-second catalog is accepted. The current Marshall issuer remains five seconds. The failure consequence is that a malformed/authenticated buggy producer's otherwise valid long catalog can be granted excess receiver freshness; this does not independently authorize a guest stream, and no production partition failure is claimed.

   If a later task authorizes this correction, narrow this class's decoder to `1..5_000` and preserve its five-second contract; add meaningful boundary cases 5,000 accepted, 5,001 and 30,000 refused, 0/wrong-type refused. Inspect its client/fleet-worker/health consumers, preserve complete-envelope/identity refusal, and run Protocol plus both Marshall/Lilly consumer gates as required for shared protocol changes. A new test must use the ADR's five-second class policy as its independent expected value, rather than importing the decoder's maximum. This is contract-preserving, unlike universally restricting common stream leases.

## Independent measurable oracle and time semantics

The independent reference model must take an explicit class selected by the workload's admitted operation, not guess a lifetime from the shared constructor's accepted range. Maintain a reviewed policy table independent of production constants: web/ordinary SSH/editor maximum 30,000; nested/catalog/DNS maximum 5,000; nested additionally no later than its publication; editor additionally no later than authenticated current login/credential/write deadlines. Keep transport request timeouts and host report liveness out of this table.

For a request observed on one Audi node, record monotonic millisecond start `s`, reply-observation time `r`, validated relative duration `t` and class maximum `M`. A valid admission requires `s <= r`, `0 < t <= M`, and `r < s + t`. Expected local expiry is exactly `E = s + t`; remaining authority at receipt is `E - r`, never `t` fresh milliseconds after receipt. At `r == E`, an arriving result is already expired. At `now == E`, `active?` is false. The pure model can use generated integer clocks, including negative starts because monotonic epochs have no wall-clock meaning, and needs no timing tolerance.

For nested publication and editor identity deadlines held in PostgreSQL wall time, check their issuer relation in the issuer's own database-time domain: stream expiry no later than current publication or current login/credential/write deadline, and advertised remaining TTL no larger than the class cap. Convert only the authenticated **relative** TTL into Audi's local clock. Never compare PostgreSQL UTC or another container's monotonic timestamp to Audi's monotonic timestamp. The outer SSH channel's start precedes backend/client work; using it is conservative and consumes all admission/renewal delay.

Renewal model: the old grant must still be active at response application (`now < old E`); the entire immutable binding must match; request start must be strictly newer than the last accepted start; the response must itself still be live. Only then replace `E` with `new s + new t`. A reply begun before expiry but applied at or after old `E` cannot resurrect. Replayed/reordered replies leave the current expiry unchanged. A definitive refusal closes the owner; inconclusive transport/late-reply errors preserve the old deadline without extension and may retry while it remains live. Hints merely trigger this real check.

Exercise delay, drop, duplicate/reorder, old expiry messages, stalled/killed renewer, suspended/killed guard, current-authority revocation and reconnect independently for each class. A useful common-lease mutant anchors `E` to receipt instead of request start; a policy mutant allows 5,001 ms catalog/nested issuance. A negative universal-five-second mutant must be caught by a valid thirty-second web/SSH/editor positive case, so the test does not accidentally institutionalize the obsolete note.

An integration oracle should keep a dedicated live connection and use fresh challenge identifiers observed by an independent guest-side receiver. For each challenge admitted after `E`, record whether the guest received it; source-observed post-expiry forwarding is a safety failure. Also monitor the resource owner and observe actual peer EOF/reset, including guard/renewer suspension. Do not assert a strict zero-millisecond process death deadline from scheduler timing alone: distinguish the exact pure decision boundary from a measured delivery/closure interval with explicit test scheduling bounds. An observation that bytes prequeued before expiry arrive later is not sufficient to prove post-expiry authorization. First bound/drain previously admitted bytes or correlate each new challenge with its admission time. The existing local socket tests demonstrate actual TCP closure but are not native Lilly/Firecracker or independent-host isolation evidence.
