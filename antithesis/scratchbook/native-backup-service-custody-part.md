## Physical boundaries and gaps

- Native storage: actual ZFS pool on `/dev/vdb` (`driver.py:13`), snapshot capture/absence and ordinary file restoration. This is one virtual disk, one pool and one storage VM; no physical power-loss/disk-loss, mirrored-storage durability, foreign-object mutation or concurrent ownership race is exercised here. Native identity/cleanup cases belong to the separately inventoried cleanup suites.
- Transport: Restic reaches fixture MinIO through HTTPS Nginx and a local trusted CA (`default.nix:95-111`); PostgreSQL source is a separate VM selected by Marshall's runtime connection and hostname certificate (`:118-142`; `driver.py:27-30`). Actual capture uses `verify-full` and minimum TLS 1.2 (`nix/domains/system/backups/postgres.py:87-99`). These sources show successful TLS use; this suite has no bad-CA/hostname negative scenario, public cloud/provider test, independent S3 failure domain or multi-host repository/password-isolation test. MinIO and backup client share the storage VM.
- Restored database: separate local port/data directory/user and fresh application boot. Loopback restore intentionally uses trust auth and omits original owners/ACLs (`driver.py:212-225`), so it does not prove production privilege reconstruction, backup authority fencing, replica promotion, PITR, or recovery of revoked credential/host/VM authority. Ordinary serving Marshall instance is disabled (`default.nix:45`).
- Crypto custody composition remains split: the native suite creates `/persistent/secrets/cloak-keyring.enc` by writing raw random-key JSON (`driver.py:15-21`); the `.enc` suffix does not represent SOPS encryption. It restores that keyring from encrypted Restic and verifies application AshCloak decryption. It selects no SOPS bundles, disables role defaults, and has empty secret-unit dependencies (`default.nix:42,77,82`), so **native ZFS → TLS S3 → restored SOPS ciphertext → identity-based SOPS decrypt → Restic access is not one native end-to-end scenario**. Only the separate evaluation check composes restore/SOPS/Restic; the service suite composes native capture/Restic restore/PostgreSQL/AshCloak.
- No Lilly service, vsock guest flush, stopped/unresponsive guest, Firecracker/jailer isolation or restored-guest serving occurs in this suite. Guest-backup coverage remains in the parent inventory. Timer text is checked, but timer scheduling is disabled; boot cleanup is manually invoked, not proved by an actual reboot in this suite. Fault coverage is controlled SIGKILL, database stop, lock contention and custody loss, not broad scheduler/fault exploration.
